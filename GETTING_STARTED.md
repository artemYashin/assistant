# Orbit: установка и первые шаги

Инструкция для новой личной установки Orbit. Нужны Git, интернет, доступ к вашему Azure DevOps и аккаунт GitHub с доступом к Copilot. Для корпоративных сервисов может понадобиться VPN. Node.js и зависимости приложения отдельно устанавливать не нужно — они собираются в контейнерах.

Если Orbit уже установлен и содержит данные, переходите к разделу «Обновление». Не выполняйте повторную инициализацию существующей установки.

## 1. Скачайте проект

Откройте терминал. На macOS/Linux можно использовать обычный терминал; на Windows — Bash в WSL 2, храня проект в домашней Linux-папке, а не в `/mnt/c`.

```bash
mkdir -p ~/projects
cd ~/projects
git clone https://github.com/artemYashin/assistant.git
cd assistant
```

Если Git отсутствует, установите его по [официальной инструкции](https://git-scm.com/downloads). Если GitHub запрашивает вход, используйте аккаунт с доступом к репозиторию.

## 2. Установите Rancher Desktop

В этой инструкции используем бесплатный Rancher Desktop вместо Docker Desktop. Docker Desktop требует платной подписки для коммерческого использования в крупных организациях; для личного использования и некоторых других случаев он остаётся бесплатным. Подробности — в [условиях Docker Desktop](https://docs.docker.com/subscription-billing/desktop-license/).

1. Скачайте Rancher Desktop с [официального сайта](https://rancherdesktop.io/) и установите версию для своей ОС и архитектуры процессора. [Инструкция установки](https://docs.rancherdesktop.io/getting-started/installation/).
2. Запустите Rancher Desktop. В настройках контейнерного движка выберите **dockerd (moby)**: для команд ниже нужен Docker CLI, а не containerd/nerdctl.
3. Kubernetes для Orbit не нужен — его можно отключить.
4. Дождитесь готовности движка. На Windows включите интеграцию с используемым дистрибутивом WSL. При необходимости переоткройте терминал, чтобы обновился PATH.
5. Проверьте доступность движка и Compose:

```bash
docker info
docker compose version
```

Если установлен также Docker Desktop, убедитесь, что команды обращаются к Rancher Desktop:

```bash
docker context ls
# Если контекст rancher-desktop есть в списке:
docker context use rancher-desktop
```

Rancher Desktop должен работать всё время, пока вы используете Orbit. Поддержка Docker CLI и Compose описана в [документации Rancher Desktop](https://docs.rancherdesktop.io/tutorials/working-with-containers/).

## 3. Первый запуск

Из папки клонированного проекта выполните:

```bash
cd ~/projects/assistant
bash scripts/first-start.sh
```

Это команда **только для новой установки без прежних данных**. Скрипт создаёт папки `docker-data/`, выставляет права для сервисов, собирает образы и запускает приложение. Вручную выполнять `mkdir`, `chown` или `docker run` не нужно.

Если папки данных уже существуют, скрипт останавливается, не перезаписывая их. Для готовой установки используйте раздел «Обновление». Если сборка не удалась после подготовки папок, исправьте причину и выполните `docker compose up --build -d`; повторная инициализация не нужна. При ошибке самой подготовки прав сохраните сообщение для диагностики, не удаляйте существующие данные.

Первая сборка может занять время: скачиваются образы и зависимости. Модель распознавания речи скачивается отдельно при первом голосовом запросе — см. пояснение ниже.

Проверьте состояние:

```bash
docker compose ps
```

Откройте **[http://localhost:43871](http://localhost:43871)** — рабочее пространство откроется без пароля. При обновлении существующей установки прежний пароль удаляется, рабочие данные и подключения сохраняются. Стандартная конфигурация доступна только на вашем компьютере; любой, кто имеет доступ к этому локальному адресу, может пользоваться Orbit.

### Где хранятся данные

База, настройки, вложения и кэши находятся в `docker-data/` внутри папки проекта. Клон в соседней папке будет отдельной установкой без этих данных. Не удаляйте `docker-data/` при обновлении.

Для резервной копии остановите контейнеры и скопируйте всю папку `docker-data/`, сохранив права. Базу и ключ `master.key` нужно сохранять вместе. Затем запустите приложение командой `docker compose up -d`.


## 4. Подключите GitHub Copilot

1. В левом сайдбаре откройте **Настройки → GitHub Copilot**.
2. Нажмите **Войти через GitHub**.
3. Откройте предложенную ссылку, введите одноразовый код и подтвердите вход нужным GitHub-аккаунтом. На странице согласия может быть указано приложение **GitHub CLI** — это используемый Orbit способ входа.
4. Вернитесь в Orbit, дождитесь завершения подключения и загрузки моделей.
5. Выберите модель или **По умолчанию в Copilot**, нажмите **Сохранить настройки**.

Доступ зависит от вашей подписки, её лимитов и политик организации. Если вход не завершился или истёк одноразовый код, начните вход заново. Подробнее: [подключение Copilot](docs/help/articles/assistant-settings.md).

## 5. Создайте Azure DevOps PAT

1. Откройте свою организацию Azure DevOps в браузере.
2. Справа сверху, слева от аватарки, откройте **User settings** → **Personal access tokens**.
3. Нажмите **New Token**, задайте понятное имя, выберите нужную организацию и срок действия.
4. Выберите **Custom defined**. Если нужных разрешений не видно, нажмите **Show all scopes**.
5. Отметьте права для тех функций, которыми будете пользоваться. Актуальная памятка есть в Orbit: **Настройки → Azure DevOps**, рядом с полем **Personal Access Token**.

Для всех перечисленных функций Orbit нужны:

| Разрешение PAT | Для чего |
| --- | --- |
| Work Items · Read & write | Читать и импортировать тикеты, менять статус и исполнителя, отправлять комментарии и вложения |
| Code · Read & write | Читать код и PR, создавать и сливать PR, отправлять комментарии к коду |
| Build · Read | Смотреть этапы CI и логи |
| Graph · Read | Искать пользователей Azure |
| Identity · Read | Получать и сопоставлять идентификаторы пользователей |

Для чтения тикетов или кода без изменений можно ограничить соответствующее разрешение уровнем **Read**. **Full access** не требуется. PAT не расширяет права вашего аккаунта: доступ к проекту, репозиторию и сборкам также должен быть выдан в Azure.

6. Создайте токен и сразу скопируйте его: Azure показывает секрет при создании, повторно посмотреть его нельзя.
7. В Orbit откройте **Настройки → Azure DevOps**, вставьте PAT, укажите фактическую дату его истечения и сохраните настройки.

Выбирайте **30 дней**, если это принятый у вас срок или максимум, разрешённый организацией. Это не универсальный предел Azure: максимальный срок задаётся политиками организации. В Orbit указывайте именно дату, которую показал Azure. См. [создание PAT](https://learn.microsoft.com/en-us/azure/devops/organizations/accounts/use-personal-access-tokens-to-authenticate?view=azure-devops) и [политики срока действия](https://learn.microsoft.com/en-us/azure/devops/organizations/accounts/manage-pats-with-policies-for-administrators?view=azure-devops).

Дата истечения интегрирована с календарём: за неделю Orbit начинает напоминать о замене токена. При замене сохраните новый PAT и новую дату. Не отправляйте токен в чат и не добавляйте его в файлы репозитория.

## 6. Просмотрите настройки

Перед началом работы пройдитесь по вкладкам **Настроек** и сохраните подходящие значения. Особенно полезно проверить:

- **Рабочее пространство**: по умолчанию включён Lead. Режим **Разработчик** скрывает управление локальными поручениями и отпусками, сохраняя тикеты, PR, память и ассистента.
- Настройки моделей, ассистента и Code Review: выберите удобные параметры и бюджеты.
- Горячие клавиши: настройте открытие чата и голосовой ввод.
- **Календарь**: выберите часовой пояс, время предварительных предупреждений и расписание уведомлений. При необходимости разрешите браузерные уведомления.

Режим работы не удаляет скрытые данные. Подробнее: [режимы работы](docs/help/articles/work-mode.md).

## 7. Создайте первого заказчика и проект

В верхней панели откройте **Заказчики и проекты** — кнопку настроек рядом с выбором контекста.

1. На вкладке **Заказчики и проекты** добавьте заказчика, затем проект этого заказчика. Названия здесь локальные: создание не создаёт проекты в Azure.
2. Выберите созданные заказчика и проект в селекторах над вкладками.
3. Откройте **Подключение Azure**. Укажите URL организации/коллекции и точное имя существующего проекта Azure. Например, URL `https://dev.azure.com/your-organization` и отдельное имя проекта. Не вставляйте в URL ссылку на тикет или репозиторий. Для собственного подключения отключите **Использовать глобальные настройки Azure**, иначе будут применяться наследуемые значения. PAT общий для приложения.
4. В **Репозиторий → Git** задайте точное имя или ID репозитория, настройте просмотр кода и загрузку. Глубина истории **0** означает полную историю; загрузка большого репозитория может занять время и место.
5. В **Репозиторий → Pull request** включите синхронизацию PR и выберите все активные PR либо нужных пользователей в списках **Required**, **Optional**, **Created by**. Условия этих списков объединяются через ИЛИ.
6. В **Репозиторий → AI review** проверьте общий лимит diff.
7. В **Автоматический импорт** настройте расписание синхронизации проекта, исполнителей Azure, типы задач и статусы. Импорт использует настроенные фильтры, а не автоматически все задачи организации или только ваши задачи.
8. Сохраняйте изменения перед переключением проекта или закрытием формы.

После настройки выберите этот контекст в хедере. На странице тикетов выполните синхронизацию или импорт нужных задач, на странице Pull Requests — синхронизацию PR.

Подробности: [заказчики и проекты](docs/help/articles/context.md), [Azure и PAT](docs/help/articles/azure-setup.md), [импорт тикетов](docs/help/articles/ticket-sync.md), [синхронизация PR](docs/help/articles/pr-sync.md).

## 8. Попросите ассистента помочь

После подключения Copilot и настройки проекта откройте чат справа. Для вопросов по интерфейсу ассистент может искать встроенную справку. Например:

- «Помоги настроить автоматический импорт тикетов для моего проекта».
- «Как включить загрузку репозитория для ревью?»
- «Объясни, откуда берутся связанные тикеты у pull request».

Данные Azure и код доступны ассистенту в пределах подключений и ваших прав. Локальный запуск Orbit не означает локальную модель: отправленные сообщения и запрошенный ассистентом контекст обрабатывает GitHub Copilot.

### Первый голосовой запрос может обрабатываться долго

**При первом использовании голосового ассистента распознавание может занять значительно больше времени, чем обычно:** после отправки записи голосовой сервис сначала скачивает модель Whisper. Скорость зависит от интернет-соединения; дождитесь завершения загрузки. Обычный текстовый запрос скачивание этой модели не запускает.

На время первой загрузки по возможности **временно отключите VPN**: он может замедлять скачивание или мешать доступу к серверу моделей. Если без VPN этот сервер недоступен или VPN обязателен по правилам вашей организации, оставьте его включённым. После загрузки верните VPN, если он нужен для Azure DevOps или других рабочих сервисов.

Модель сохраняется в `docker-data/whisper` и используется повторно. Пока этот кэш сохранён, при следующих голосовых запросах, перезапусках и обновлениях скачивать её заново не нужно; загрузка модели в память и само распознавание всё равно занимают некоторое время.

## Обновление

Запустите Rancher Desktop, откройте терминал и перейдите **в ту же папку**, где установлен Orbit:

```bash
cd ~/projects/assistant
docker compose stop && git pull --ff-only && docker compose up --build -d
```

Эту команду можно использовать при каждом обновлении: приложение остановится, Git скачает изменения, Compose пересоберёт образы и запустит контейнеры в фоне. `git pull` — команда Git, а не подкоманда `docker compose`. `&&` запускает следующий шаг только после успешного предыдущего.

Папки данных сохраняются; миграции приложения выполняются при запуске. Перед обновлением полезно сделать резервную копию, особенно перед крупными версиями. Не удаляйте данные и не сбрасывайте Git принудительно, если обновление сообщает об ошибке.

Если `git pull` остановился из-за локальных правок или расхождения веток, контейнеры останутся остановленными. Сохраните свои изменения и разберите сообщение Git. Пока обновление не выполнено, прежние контейнеры можно вернуть командой:

```bash
docker compose start
```

Если не удалась сборка, исправьте причину и повторите `docker compose up --build -d`. При ошибках запуска смотрите состояние и логи:

```bash
docker compose ps
docker compose logs --tail=100 orbit code-browser voice
```

## Если что-то не запускается

| Симптом | Что проверить |
| --- | --- |
| `docker: command not found` или отсутствует `compose` | Установка Rancher Desktop, интеграция CLI/PATH; переоткройте терминал |
| Не удаётся подключиться к Docker daemon | Rancher Desktop запущен, выбран dockerd (moby), активен нужный Docker context |
| Не найдена папка bind mount | Для новой установки выполнен `bash scripts/first-start.sh`; для существующей — папки `docker-data/` доступны по прежнему пути |
| Страница localhost не открывается | `docker compose ps` и логи; дождитесь запуска после сборки |
| Azure отвечает 401/403 | Срок PAT, его scopes, права аккаунта, URL подключения и корпоративные ограничения |
| Не видны тикеты или PR | Выбран нужный проект, сохранено подключение и репозиторий, фильтры импорта соответствуют нужным данным |
| Сервис недоступен через VPN | Доступ и DNS должны работать из контейнеров, а не только из браузера хоста |

При передаче логов для диагностики убирайте токены и приватные данные. Полное руководство по хранению и восстановлению: [Docker storage](docs/DOCKER_STORAGE.md).
