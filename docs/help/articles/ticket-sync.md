# Синхронизация и импорт тикетов

## Ручное обновление
Кнопка синхронизации тикетов относится к тикетам; не запускает ревью/полный цикл всех разделов.
«Синхронизировать тикеты» получает ID по исполнителям, типам и статусам, сохранённым в «Заказчики и проекты» → «Автоматический импорт». Затем объединяет их с уже сохранёнными локальными ID. Ручная синхронизация использует фильтры даже при выключенном фоновом автоимпорте. Инструмент ассистента sync_tickets работает так же. При пустом списке исполнителей обновляются только уже добавленные тикеты.
Этап 1 обновляет задачи, подходящие под фильтры. Этап 2 — остальные отслеживаемые задачи, даже если они назначены другому человеку. Пакеты до 200 ID. Локальная корзина исключается.
## Что сохраняется
Запрашиваются название, статус, исполнитель, тип, даты, Azure-теги, проект, описание, критерии приёмки и шаги воспроизведения. Поэтому описания могут появляться в кэше уже при синхронизации, не только после открытия деталки. Открытие деталки обновляет кэш ещё раз. Локальные заметки/теги/приоритет не подменяются значениями Azure.
## Автоимпорт и расписание
Заказчики и проекты → Автоматический импорт: включение, список «Исполнители» и выбранные типы/статусы. Для автоматического импорта фильтры не должны быть пустыми. Ручная синхронизация использует те же фильтры.
Общее расписание ограничивает фоновые обновления; ручные доступны вне расписания.
## Пограничные случаи
Если Azure возвращает неполный пакет, показывается ошибка; нельзя считать весь цикл успешным. Ранее успешно сохранённые пакеты могут уже быть обновлены. При смене подключения во время запроса операция защищается от записи в чужой контекст.
Ранее удалённые тикеты не возвращаются автоматически. Восстановление — явное действие. Недоступный/удалённый в Azure ID может привести к ошибке обновления пакета.
Импорт по номеру проверяет существование и Azure-проект. Azure-поиск позволяет читать или импортировать выбранное; не смешивайте просмотр и добавление.
Кнопка обновления PR может дополнительно импортировать недостающие связанные тикеты, но это не полный цикл обновления всех тикетов.


Фильтры и включение автоимпорта сохраняются отдельно для каждого проекта Orbit. Таймер и расписание находятся в этой же вкладке «Автоматический импорт». Фоновый цикл проверяет каждый проект независимо от активного проекта в хедере, применяя его интервал, дни и часы. При общем Azure-подключении уже полученные тикеты в одном проходе повторно не скачиваются; фильтры поиска новых задач остаются проектными. При первом обновлении старые общие фильтры копируются во все существующие проекты без удаления тикетов. Последующие изменения независимы; новые проекты начинают с выключенным автоимпортом и пустыми фильтрами. Переименование переносит настройки, удаление проекта удаляет только его настройки импорта. Нажатие «Сохранить» само не запускает импорт.

### Исполнители автоимпорта
В «Заказчики и проекты» → «Автоматический импорт» найдите пользователей Azure по имени или e-mail и добавьте в «Исполнители». Поиск требует минимум двух символов. Можно выбрать до 50 пользователей. Новые тикеты ищутся серверным WIQL-запросом в выбранном Azure-проекте: любой выбранный исполнитель И один из выбранных типов И один из выбранных статусов. Все тикеты организации не скачиваются. Авторы тикетов не входят в этот фильтр. Владелец PAT автоматически не подставляется.
Для включения и сохранения автоимпорта нужны исполнители, типы и статусы. Старые настройки без исполнителей не ищут новые тикеты, пока список не заполнен; уже отслеживаемые тикеты продолжают обновляться. Запрос AssignedTo=@Me больше не используется при синхронизации. Пользователи Azure для фильтра не добавляются в локальный справочник разработчиков.

При импорте, синхронизации и загрузке деталки сохраняется «Azure приоритет» (Microsoft.VSTS.Common.Priority). Он хранится отдельно от локального приоритета по Azure-подключению и ID тикета. Обновление создаёт дополнительную таблицу без удаления существующих данных; старые тикеты получают значение после следующей синхронизации. Если Azure не возвращает поле, оно остаётся пустым, а не заменяется на 1. Корзина сохраняет значение до истечения её срока хранения.
