# Напоминания через ассистента

Попросите, например, «Найди старые завершённые напоминания о релизе» или «Найди напоминания за октябрь, сначала новые». Инструмент `search_calendar_reminders` ищет по названию и описанию во всех уровнях независимо от выбранного проекта, включая завершённые записи. Доступны буквальный поиск без учёта регистра и `searchMode: regex` (RE2, без /…/, lookaround и обратных ссылок). Неверный шаблон возвращает ошибку.

Фильтры: ID, завершённость всей записи (`all/open/completed`), текущие состояния, виды (обычное напоминание, событие, без срока, ежедневная серия, дедлайн тикета), уровни, заказчики, проекты, локальные разработчики, диапазон события и диапазон создания. В массивах действует ИЛИ, между фильтрами — И. Диапазон события включает частичное пересечение и границы; без даты запись не попадает в датированный диапазон. Для серии возвращается одна запись, а состояние относится к сегодняшнему дню, не к прошлым итерациям. Сортировка — по началу, окончанию, дедлайну тикета, созданию или названию, в любом направлении; пустые даты идут последними. Результат содержит до 50 кратких записей с выдержкой описания до 240 символов и ссылками на календарь; остальные доступны через пагинацию. Удалённые напоминания не восстанавливаются поиском.

## Действия без дополнительных подтверждений

Явная просьба в чате — основание выполнить действие сразу, без открытия формы или confirmation-попапа. `save_calendar_reminder` создаёт или редактирует напоминание (ID опционален при создании); для изменения существующего содержимого ассистент сначала читает полную запись через `get_calendar_reminder`, чтобы сохранить не затронутые просьбой поля. Сроки разрешаются через `get_calendar_context`. Неоднозначные даты или выбор конкретного напоминания могут потребовать уточнения.

`change_calendar_reminders` принимает действие `complete`, `reopen` или `delete` и массив до 500 записей с точными ID. Для обычного напоминания и дедлайна тикета используется `target: reminder`; для отдельного повтора — `occurrence` и необязательная дата `day` YYYY-MM-DD в часовом поясе серии (по умолчанию сегодня); для всей серии — `series`. Просьба «завершить все напоминания» включает дедлайны и целые ежедневные серии, если пользователь не ограничил выборку. В других неоднозначных случаях ассистент уточняет отдельную итерацию или серию.

Перед массовым действием ассистент собирает все страницы результатов поиска, затем меняет записи, чтобы изменения фильтра не приводили к пропуску следующей страницы. Точные дубликаты внутри пачки учитываются один раз. Каждая пачка сохраняется одной транзакцией: если запись не найдена или параметры неверны, вся пачка откатывается. При нескольких пачках ранее успешные сохраняются; ассистент должен сообщить фактический результат, а не заявлять успех всего запроса после ошибки.

При удалении обычные напоминания и явно выбранные серии удаляются необратимо. Напоминания о дедлайнах тикетов вместо удаления **завершаются**: сам тикет, его локальный дедлайн и заметки сохраняются. Отдельный повтор можно завершить, но не удалить. Ответ инструмента содержит отдельные количества удалённых, завершённых и возобновлённых записей. Azure не изменяется. Завершённые напоминания можно вернуть в незавершённые. Уведомления возобновляются по общему таймеру и расписанию.

Календарь и уведомления обновляются после успешного действия без открытия попапов. Прямые действия доступны только чат-ассистенту, не ревьюеру. Ручные кнопки календаря по-прежнему запрашивают подтверждение.

## Индивидуальное предупреждение

`get_calendar_context` возвращает общие интервалы. В `save_calendar_reminder` поле `reminder.leadMinutes` задаёт целое число минут от 0 до 525600 либо `null` для общей настройки. Значение действует и для ежедневной серии, включая предупреждение накануне. Поиск возвращает `leadMinutes` и `effectiveLeadMinutes` (фактически используемый интервал).

`update_calendar_warning` сразу сохраняет новый интервал существующего напоминания, включая дедлайн тикета, по точному ID и `leadMinutes`. Он не меняет дату, статус завершения или данные Azure. Для возобновления или завершения будущей итерации `change_calendar_reminders` принимает `target: occurrence` и её дату `day`; остальные даты и вся серия сохраняются.

В результатах поиска `start` у дедлайна тикета — его фактический срок, `warningStart` — отдельное начало предварительных предупреждений. Сортировка по началу и фильтр диапазона дат для таких записей используют сам дедлайн. Изменение `leadMinutes` не переносит событие в календаре.

В `save_calendar_reminder` поле `reminder.repeatWeekdays` задаёт дни повторения: массив ISO-номеров 1 (понедельник) — 7 (воскресенье), минимум один день. Оно применяется при `repeatDaily: true`; без него выбраны все дни. Полное чтение и поиск возвращают выбранные дни. Для просьбы «без времени» ассистент передаёт `start: null`, `end: null`, `repeatDaily: false` — это постоянное напоминание «Без срока», а не событие на весь день.

«Напомни через пять минут» задаёт дату начала через пять минут, а не индивидуальное предупреждение. При создании ассистент должен не передавать `leadMinutes` или передать `null`, если пользователь отдельно не указал интервал предупреждения. Так сохраняется общая настройка: при предупреждении за час напоминание через пять минут уже доступно под колокольчиком. Результат сохранения возвращает `start`, `leadMinutes`, `effectiveLeadMinutes` и `warningStart`, чтобы ассистент мог проверить фактические сроки. При редактировании существующее индивидуальное предупреждение сохраняется, если пользователь не просил его менять.

Фильтр поиска `statuses: ["recurring"]` находит серии по признаку повтора, в том числе завершённые сегодня и завершённые целиком. Для исключения завершённых целиком используйте также `completed: "open"`. Фильтр `today_completed` проверяет только сегодняшний день в часовом поясе серии; разные статусы в массиве объединяются через ИЛИ. Поиск возвращает одну запись на серию, а не создаёт записи для каждого дня.

`search_calendar_reminders` поддерживает `types: ["reminder", "ticket"]`: `reminder` — все обычные напоминания, включая повторяющиеся, с длительностью и без времени; `ticket` — дедлайны тикетов. В результате есть поле `type`. Пустой массив или отсутствие `types` не ограничивает тип. Внутри массива — ИЛИ, между типом, состояниями, заказчиками, проектами, датами и другими фильтрами — И. `statuses: ["active"]` соответствует «Все активные» (не завершённые целиком). Прежний `kinds` сохраняется для более точного выбора, например `daily`. Существующие фильтры по статусам, включая `recurring` и `today_completed`, заказчикам и проектам поддерживают массивы. Настройка фильтров интерфейса не ограничивает поиск ассистента автоматически: он передаёт нужные параметры при поиске.

Отпуска доступны через `types: ["vacation"]` и `kinds: ["vacation"]` в `search_calendar_reminders`, вместе с датами, статусами, уровнем и разработчиками. Результат содержит `vacation` (ID разработчика, даты включительно, пояс, возвращение), `warningStart` и фактический интервал предупреждения. `list_local_developers` возвращает `vacationStart`, `vacationEnd`, `vacationZone`. `get_calendar_context` возвращает общий `vacationLeadMinutes`. Завершение или удаление напоминания об отпуске выключает уведомления, но не отменяет период отсутствия; после даты возвращения уведомления прекращаются автоматически. `update_calendar_warning` поддерживает отпуск. Даты отпуска меняются только в настройках разработчика; обычное сохранение календарного события их не изменяет. Подробности: [Отпуска разработчиков](developer-vacations.md).
