# Git: загрузка, кэш и диагностика

## Что делает сервис
Отдельный code-browser хранит локальные Git-объекты и снимки. Чтение файла использует объект соответствующей ветки/ревизии; это не обязанность делать общий checkout на каждый клик. Поиск использует локальные файлы снимка.
Проверить обновляет сведения о remote; Pull обновляет выбранный снимок. Обновление страницы присоединяется к текущей работе и не должно создавать вторую загрузку того же запроса.
## Настройки
Репозиторий → Git: depth 1–1000, default 1; тайм-аут 1–120 минут, default 5; синхронизация 0–1440 минут, default 30 (0 — вручную).
Depth — глубина истории коммитов, не количество файлов. Новая ветка может потребовать объектов/деревьев/истории; увеличение depth увеличивает первоначальную загрузку и не гарантирует уменьшение каждого последующего fetch.
Фоновая проверка использует общее расписание, обновляет ветки и проверяет последнюю открытую ветку уже загруженного репозитория. Она не заменяет явный Pull открытого снимка.
## Прогресс и отмена
Показываются этап, проценты, при наличии Git-данных — полученный объём/скорость. Это не гарантированный ETA всего процесса. Очередь показывает ожидающие операции; обычные чтения файлов не должны раздувать прогресс.
Отладка текущей работы показывает jobs и позволяет отменить текущие/ожидающие задачи. При переключении ветки старая работа может отменяться. Отмена не является удалением всего кэша.
Сон Mac может приостановить Docker/сеть; низкая скорость не доказывает проблему токена. Не обещайте докачку незавершённого pack с точного байта: Git переиспользует уже сохранённые валидные объекты, но не гарантирует resume частичного потока.
## Ошибки
shallow.lock / File exists: возможны активная операция или остаточный lock. Не удаляйте lock живого Git. Используйте штатную диагностику/безопасное восстановление сервиса.
Лимит кэша: актуальная реализация сохраняет скачанные данные и просит увеличить CODE_BROWSER_MAX_CACHE_BYTES в .env и пересоздать code-browser. Не начинайте с удаления всего тома. Default сервиса 20 GiB; deployment может переопределить.
Тайм-аут Git задаётся в настройках репозитория. Ожидание чатом готовности (default 20 секунд, до 120) — другой лимит, не время разрешённой загрузки.
