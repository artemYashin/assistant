# Деталка тикета

## Как открыть

Кнопка открытия тикета в хедере или настроенный хоткей (по умолчанию T) открывают ввод номера. В связанных тикетах PR и в карточках разработчиков «Открыть тикет»/название открывают попап. Ассистент может открыть один или несколько тикетов; при нескольких слева появляется список для переключения.
Копирование иконкой ссылки копирует Azure URL, не открывает его. Кнопка перехода к тикету в деталке ведёт в страницу тикетов.

## Содержимое

В левой части — краткие поля/локальная информация; основная часть разделена на вкладки «Содержание», «Заметки», «Связанные PR», «Ссылки», «Вложения» и «История». В «Содержании» находятся описание, шаги воспроизведения и критерии приёмки; под ними — свёрнутый по умолчанию аккордеон «Комментарии» со счётчиком и редактором нового комментария. У вкладок PR, ссылок и вложений показано количество элементов в цветных бейджиках; история загружается отдельно. При переключении вкладок в открытой деталке сохраняются прокрутка, раскрытые разделы и черновик комментария. После закрытия окна или перехода к другому тикету выбранная вкладка и прокрутка сбрасываются; это не сохранение между перезагрузками. Окно просмотра нескольких тикетов расширено, чтобы вместить список слева. Тип/статус отображаются цветами из настроек.
Изображения открываются для увеличения. Для них резервируется место, чтобы загрузка не сбивала позицию цитаты. Ссылки сохраняются, Markdown-код имеет подсветку и копирование.

## Ссылки из содержимого

Во вкладке «Ссылки» собраны зелёные
бейджики ссылок из описания,
критериев приёмки, шагов воспроизведения и загруженных комментариев. Они показаны вертикальными списками в отдельных блоках: описание, шаги
воспроизведения, критерии приёмки и каждый загруженный комментарий — в порядке
разделов в деталке. Внутри блока сохранён порядок появления ссылок. Длинные
подписи и адреса показываются полностью с переносом текста, без многоточий. Нажатие на подпись открывает
адрес в новой вкладке, отдельная кнопка копирует исходный URL. Рядом находится
кнопка-иконка «Показать в тикете»: она открывает «Содержание» и раскрывает исходный раздел или аккордеон «Комментарии»,
прокручивает к ссылке и подсвечивает её в содержимом текущей деталки. Другой
попап не открывается. Для повторяющихся URL переход ведёт к месту, из которого
взята выбранная подпись в текущем блоке. Если содержимое изменилось и найти ссылку не удалось,
во вкладке «Ссылки» появляется сообщение об этом.

Список строится обычным парсингом HTML/Markdown уже загруженной деталки, без LLM
и дополнительных запросов в Azure. Одинаковые URL объединяются только внутри одного блока; в разных разделах
ссылка сохраняется в каждом из них. Подпись берётся
из текста ссылки, при его отсутствии показывается адрес. Полный адрес виден
при наведении. Поддерживаются HTTP/HTTPS, в том числе обычные текстовые URL;
адреса изображений без гиперссылки, примеры внутри кода и локальные прокси
вложений в список не попадают. Если ссылок нет, вкладка показывает пустое состояние.
При просмотре сохранённой версии список соответствует этому кэшу. Содержимое
тикета в Azure и локальные данные не изменяются.

## Загрузка и кэш

Открытие получает актуальную деталку из Azure и обновляет локальные данные/кэш. При неудаче, если кэш существует, показывается сохранённая версия с предупреждением сверху. Это не подтверждение актуальности. Если кэша нет, нечего показать — остаётся ошибка.
Просмотр попапа сам по себе не означает добавление задачи в локальный рабочий список. Если задача не отслеживается, доступно добавление. Задача из корзины помечается отдельно.

## Ассистент и цитаты

Analyze with AI раскрывает чат и прикрепляет выбранный тикет к следующему сообщению. Бейдж можно снять крестиком. При отправке он исчезает у ввода, остаётся у сообщения; при ошибке отправки контекст может быть восстановлен.
«Показать в тикете» открывает нужный раздел, находит точный процитированный текст, подсвечивает его и прокручивает к нему. Изменившийся текст может не совпасть; нельзя утверждать, что старой цитаты нет в истории Azure.
Список в попапе передаёт выбранный тикет, не все автоматически. Инструмент закрытия деталки у ассистента раскрывает чат.

## Комментарии с Markdown и картинками

В разделе комментариев визуальный редактор сразу показывает форматированный текст. Пристыкованная сверху панель с иконками поддерживает жирный текст, курсив, списки, цитаты, ссылки и блоки кода. Выделите текст и нажмите нужную иконку; доступны стандартные сочетания клавиш и отмена изменений. Результат отправляется как Markdown с преобразованием в безопасный HTML для Azure. Произвольный HTML удаляется при отправке.
Кнопка «Картинка», вставка изображения из буфера в поле текста и перетаскивание файлов в редактор добавляют изображения в черновик. Можно добавить до 10 изображений PNG, JPEG, GIF или WebP, каждое до 10 МБ. Изображение сразу отображается внутри текста, ещё до загрузки в Azure. Карандаш у картинки открывает изменение её описания и кнопку «Удалить картинку»; у ссылки — изменение текста и адреса либо «Удалить ссылку» с сохранением текста. Справа сверху переключатель «Markdown / Редактор / Предпросмотр»: по умолчанию открыт визуальный «Редактор». «Markdown» позволяет менять исходную разметку, «Предпросмотр» отключает редактирование и скрывает карандаши. Текст и картинки сохраняются при переключении режимов. Вставка картинок из буфера и перетаскивание работают также в Markdown. Локальные картинки показываются через разрешённые политикой безопасности blob-адреса, до загрузки на сервер; размер ограничен 480 × 240 пикселями и шириной поля с сохранением пропорций.
Enter в текстовом поле создаёт новую строку или абзац и не отправляет комментарий; Enter на кнопке отправки также не публикует его. Только явное нажатие «Отправить» загружает используемые картинки в Azure, получает ссылки и публикует комментарий с этими ссылками. Требуется PAT с Work Items Read & write. До отправки файлы остаются в памяти браузера; сервер не хранит их на диске. Ограничение текста вместе с конечными ссылками — 10 000 символов.
Перед публикацией комментария Orbit привязывает использованные загруженные картинки к тикету в Azure как вложения (`AttachedFile`). Это позволяет Azure учитывать связь файла с тикетом при доступе других пользователей; их права на сам тикет по-прежнему действуют. Существующие привязки не дублируются. Если привязать файл не удалось или тикет одновременно изменился, комментарий не публикуется: повторите отправку после устранения ошибки. Если привязка прошла, но публикация комментария не удалась, вложения остаются у тикета и используются повторно.
Обновление не меняет схему хранения, старые комментарии, черновики загрузок и записи успешной отправки. Ранее опубликованные комментарии автоматически не исправляются: при недоступности старой картинки для коллег прикрепите исходный файл к тикету в Azure и при необходимости отправьте комментарий с новой ссылкой.

При ошибке текст, файлы и полученные ссылки остаются в черновике; повторная отправка использует уже загруженные картинки. Закрытие и повторное открытие деталки сохраняет черновик в рамках текущей страницы. Перезагрузка страницы или закрытие вкладки его удаляет. После успешной отправки редактор очищается, комментарий и изображения доступны в деталке.
Если картинки уже загрузились, но комментарий не отправлен, вложения остаются в Azure. Удаление картинки из черновика не удаляет её с сервера. Orbit хранит локально только сведения об успешной загрузке и отправке для повторных запросов, не сами файлы. Если соединение оборвалось после обработки запроса Azure, но до получения ответа сервером Orbit, исход операции может быть неизвестен: проверьте комментарии в Azure перед повтором.

## Просмотр выбранных тикетов

В разделах «Тикеты», «Azure тикеты» и «Корзина» отметьте один или несколько тикетов: рядом с «Отображение» появится кнопка «Просмотреть». Она открывает выбранные тикеты в одном попапе со списком слева. Сначала загружается первый тикет, остальные — при переключении; весь список не обрезается до 50 элементов. Справа от «Просмотреть» показано количество выбранных тикетов. При снятии всего выделения кнопка скрывается. Просмотр не импортирует и не восстанавливает тикеты из корзины. Деталка использует обычную загрузку из Azure с сохранённым кэшем при ошибке.

В списке выбранных из таблицы тикетов под названием показаны тип и статус цветными бейджиками, как в таблице. Они используют данные на момент открытия списка и настроенные цвета типов и статусов.

Во вкладке «Вложения» изображения показаны компактными блоками по размеру содержимого, со светлым фоном и разделителями между вложениями. Служебная подпись «Изображение в тексте» скрыта; имена прикреплённых файлов сохранены. У изображений есть зелёная кнопка с иконкой и подписью «Показать в тикете»: она открывает вкладку с первым вхождением картинки в описании, критериях, шагах или комментариях, прокручивает к ней и выделяет рамкой. Если изображение только приложено файлом, показывается сообщение, что в тексте его нет; просмотр самого вложения остаётся доступен. Переходы к ссылкам и цитатам также открывают нужную вкладку. Эти действия не меняют данные в Azure.

## История Azure

Вкладка «История» загружает изменения только при первом открытии, по 20 записей от новых к старым. «Загрузить ещё» добавляет более старые записи в конец. При первом открытии читается текущая версия тикета; новые изменения, появившиеся во время просмотра, не сдвигают страницы. Чтобы увидеть их, откройте деталку заново. «История» находится последней справа. Каждая запись — отдельный свёрнутый аккордеон с автором, аватаркой с инициалами, временем и версией. Раскрытые изменения имеют боковые отступы от рамки. Внутри показаны только исполнитель, статус, описание, критерии приёмки и теги: название поля и значения «Было» и «Стало», без вложенных аккордеонов. HTML показывается безопасным текстом без загрузки старых изображений. Записи, где менялись только остальные поля, связи или вложения, скрыты. Пагинация идёт по исходным записям Azure: если на странице нет основных изменений, «Загрузить ещё» остаётся доступной, пока есть следующие страницы.

Нужны действующее подключение Azure и права PAT на чтение Work Items. История читается через [Azure Updates API](https://learn.microsoft.com/en-us/rest/api/azure/devops/wit/updates/list?view=azure-devops-rest-7.1); она не изменяет тикет. Локальные поручения, заметки, приоритет и дедлайн Orbit сюда не входят. История остаётся загруженной при переключении вкладок открытой деталки, но не сохраняется в базе или между перезагрузками. Чтобы загрузить свежие изменения, откройте деталку заново.

При ошибке уже загруженные страницы остаются видны, кнопка «Повторить» повторяет неудавшуюся страницу. Если подключение Azure изменилось, загрузите тикет заново. При просмотре сохранённой деталки без доступа к Azure сама история недоступна: отдельного офлайн-кэша у неё нет.

## Связанные PR из Azure и Orbit

Во вкладке «Связанные PR» объединяются явные связи Azure Work Item (ArtifactLink) и связи с синхронизированными PR Orbit: ручные привязки и найденные упоминания тикета. Совпадение репозитория и номера PR даёт одну запись с пометкой «Azure и Orbit». Связи Azure видны и для завершённых/отклонённых PR, и для репозиториев, не подключённых к синхронизации Orbit.

При открытии деталки связи Azure сохраняются вместе с ней без отдельного запроса. Названия, авторы и статусы связанных Azure PR запрашиваются только при первом открытии вкладки, не более четырёх запросов одновременно. «Обновить PR» повторяет загрузку метаданных; вкладка не загружается повторно при обычном переключении. Для старых сохранённых деталок без списка связей сначала выполняется дополнительное чтение relations тикета. Ошибка отдельного PR показывается возле него и не скрывает остальные связи; при ошибке чтения relations сохраняется локальный список с предупреждением. Для чтения Git PR нужны права PAT на Code Read.

Активный PR из локального списка открывается в обычном разделе Pull Requests. Остальные открываются там же в отдельном точечном режиме просмотра; для завершённых/отклонённых выбирается вкладка «Завершённые». В этом режиме используется обычная карточка с «View Diff», списком коммитов и изменениями отдельного коммита; просмотр не добавляет PR в синхронизацию. Если PR уже известен Orbit, в точечном просмотре доступны его последний сохранённый результат ревью и история, как в списке «Завершённые». Открытие не ведёт в Azure. Подробности — [Завершённые PR и переимпорт](pr-completed.md). Локальные привязки и отметки «Не учитывать» не изменяются; явная связь Azure может показываться независимо от исключения тикета из ревью.

Поле «Локальные теги» в деталке и его редактор изменяют только теги Orbit. Поле «Azure теги» и теги в истории Azure остаются отдельными данными.

Во вкладке «Заметки» справа от «Содержание» доступен Markdown-редактор локальных заметок с картинками. Нажмите «Сохранить»: автосохранения нет. Переключение вкладок деталки сохраняет черновик; перед закрытием окна сохраните его. Для тикетов вне локального списка доступно чтение заметок и подсказка добавить тикет. Заметки не отправляются в Azure; прежний текст и изображения используются без переноса данных.
