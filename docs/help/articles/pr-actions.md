# Действия PR: ветки, Draft и Abandon

В списке pull request слева от названия есть иконка «Скопировать ссылку на PR»: она копирует Azure-ссылку в буфер обмена, не открывая PR. После копирования появляется «Скопировано», при недоступном буфере — сообщение об ошибке. Бейдж «AI review не запускалось» относится именно к автоматическому AI review в Orbit, а не к ревью других участников в Azure.

## Ветки и версия

Source — откуда берутся изменения; Target — куда их объединяют. Синие бейджи открывают ветку в Коде репозитория, копирование рядом копирует имя. Версия коммитов и версия diff помогают понять, что именно анализировалось.
«Загрузить source ветку» подготавливает локальный код; недоступна при уже готовой/загружаемой ветке. Готовность Git не означает пройденный CI.

## Создание

«Создать PR» открывает выбор репозитория/веток и описание/название. Селекторы Source и Target ищут актуальные ветки напрямую в Azure: запрос отправляется через 250 мс после изменения строки поиска, а список обновляется при каждом открытии селектора. Во время поиска внутри списка и на кнопке отображается индикатор «Ищем ветки в Azure…»; «Ничего не найдено» появляется только после завершения загрузки. Ответ старого запроса не заменяет результаты нового. Обычный поиск возвращает первые 100 веток; если их больше, уточните поиск. В Source наверху дополнительно показаны существующие ветки из последних 100 push текущего владельца PAT, от новых к старым. Под названием такой ветки мелким текстом показано время последнего вашего push: «updated now», «updated 10 minutes ago» или «updated 1 day ago». Подпись обновляется раз в минуту; при наведении видны точные дата и время. Если дата неизвестна, подпись не показывается. Это порядок по вашим push, а не по автору коммита или имени ветки. Target сохраняет обычный порядок. Если Azure не позволяет получить личную активность, появляется подсказка и используется обычный список; создание PR остаётся доступным. Escape при открытом селекторе закрывает только список, сохраняя попап создания PR. Ошибка Azure отображается под селектором; повторное открытие запускает новую попытку. Проверьте source и target до отправки. Это серверное действие Azure, требующее Code Read & write; не создавайте повторно при неясном ответе без проверки.

### Название и описание

После выбора Source название заполняется первой строкой последнего коммита этой ветки, до 400 символов. Название можно исправить вручную: последующие ответы Azure и смена ветки не перезаписывают ручной текст. Кнопка «Использовать название из последнего коммита» явно заменяет его актуальным сообщением выбранной ветки. Пока читается коммит (автоматически после выбора Source или по кнопке), поле «Название» заблокировано, а в кнопке крутится индикатор загрузки. Если коммит прочитать не удалось, введите название самостоятельно.

«Описание» использует Markdown-редактор с форматированием, режимами «Редактор», «Markdown» и «Предпросмотр». Скриншоты можно вставлять из буфера, перетаскивать или выбирать файлом. Поддерживаются PNG, JPEG, GIF и WebP: до 10 изображений по 10 МБ. До отправки файлы находятся в открытой форме, а не в Azure. При закрытии окна несохранённые файлы и текст теряются. Лимит описания — 20 000 символов, включая итоговые ссылки на изображения.

При создании изображения загружаются как вложения **самого PR** в Azure, затем ссылки на них записываются в описание. Они доступны другим участникам с правом чтения этого репозитория и не зависят от вашего браузера или локального Orbit. Требуется PAT с Code: Read & Write. Вставлять локальные `blob:`, `data:` или localhost-ссылки вместо прикрепления файла нельзя. Просмотр этих вложений внутри Orbit использует существующее защищённое проксирование изображений Azure.

### Ошибки и повтор отправки

Во время отправки форма заблокирована. Если сервер подтвердил, что создание ещё не начиналось (например, отклонены поля или файл), поля снова доступны для исправления; текст и изображения остаются. При неизвестном результате сохраняется исходный запрос для «Повторить отправку»; не закрывайте форму до завершения. Если PR уже создан, но описание или вложения не сохранены полностью, результат показывает его номер и кнопку «Повторить сохранение описания». Повтор работает с тем же PR, сохраняя уже загруженные файлы. Подтверждённый номер и этап операции хранятся на сервере, поэтому перезапуск сервера не заставляет повтор из открытой формы создать ещё один PR.

Если ответ Azure на само создание потерян и номер неизвестен, автоматическое повторное создание блокируется: сначала проверьте список PR. Если активный PR между выбранными ветками существовал до запроса, Orbit показывает его номер, но не меняет его описание и не прикрепляет к нему файлы из новой формы. Ошибка обновления локального списка после создания показывается отдельно и не отменяет созданный PR.

Существующие PR, настройки и файлы не переносятся и не удаляются. Служебные записи для безопасного повтора добавляются в существующее хранилище; миграция схемы базы не требуется. Форма доступна и в Lead, и в Developer; инструменты чат-ассистента и ревьюера не меняются.

## Состояние

Mark as Draft переводит в черновик, Unmark as Draft возвращает из него. Abandon закрывает PR без слияния, не удаляет ветку и не объединяет код. Такие действия имеют подтверждение; затем состояние PR перечитывается. Изменение может остановить текущее автоматическое ревью.
Кнопки Set Auto Complete нет. Merge — отдельный процесс со своей формой и проверками.
Завершённая карточка доступна для чтения, diff, коммитов, результата ревью и переимпорта, а не для обычного повторного merge.

## Изображения в описании

Нажмите изображение в «Описание pull request», чтобы открыть просмотр с масштабированием.
Фоновое обновление локальных данных PR не закрывает открытую картинку и не сбрасывает
масштаб, пока адрес этой картинки остаётся прежним. Закрыть просмотр можно крестиком
или Escape. Если источник изображения изменился, старое превью закрывается — откройте
обновлённую картинку повторно.

В сохранённых описаниях PR поддерживаются встроенные `data:image/...;base64` изображения PNG, JPEG, GIF и WebP, включая HTML-теги `<img>`. Это работает в обычном списке, завершённых PR и точном просмотре. Orbit проверяет содержимое и тип изображения, показывает локальное превью и позволяет увеличить картинку. Произвольный HTML не исполняется, примеры кода не превращаются в изображения. Ограничения: до 10 МБ на картинку и 20 МБ встроенных изображений на описание. Повреждённые или неподдерживаемые изображения остаются недоступными.

Исходные описания в базе сохраняются без переписывания: старые записи поддерживаются при чтении, миграция не нужна. Настоящие `blob:`-ссылки из другого браузера не содержат байтов картинки и не могут быть восстановлены; для них остаётся сообщение о недоступном превью. При создании нового PR прикрепляйте файлы через редактор: они по-прежнему загружаются в Azure как вложения PR, а не публикуются локальными ссылками.

Вложения PR отображаются через локальный `/api/pr/image`, а не прямым запросом браузера в Azure. Поддерживаются ссылки как с GUID, так и с подтверждённым именем репозитория; при чтении ссылки по имени Orbit дополнительно проверяет репозиторий в Azure. Это исправляет просмотр скриншотов в PR, созданных прежними версиями формы: повторно прикреплять файлы не нужно. Проверки организации, проекта и номера PR сохраняются. Если разрешённое превью получить нельзя, вместо прямой внешней загрузки показывается «предпросмотр недоступен»; расширять CSP или отключать защиту браузера не требуется.
