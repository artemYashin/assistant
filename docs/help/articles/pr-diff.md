# View Diff и коммиты

«View Diff» открывает изменения PR. Слева дерево папок и файлов с размером и количеством добавленных/удалённых строк, справа сравнение до/после. Папки сворачиваются; отступ вложенности компактный — 8 пикселей на уровень, чтобы длинные имена занимали меньше места по горизонтали. Статус слева: + — добавлен (зелёный), − — удалён (красный), M — изменён (синий), R — переименован. Для переименования подсказка показывает старый и новый путь. Выберите файл; язык подсветки можно выбрать/определить автоматически. Плюсы/минусы — структура diff, не часть исходного кода.
Комментарии к строкам отображаются в компактных аккордеонах; закрытое состояние показывает автора и строку. Отдельный блок обсуждений позволяет раскрыть текст и перейти к строке. Путь файла и кнопка перехода помогают отличить обсуждения.
«Коммиты» открывает список коммитов и просмотр их изменений. Исключения путей общие для ревью и View Diff, в том числе коммитов; исключённые файлы остаются в дереве, но их содержимое не загружается.
Заказчики и проекты → Репозиторий → Git: исключённые пути/маски; до 100 правил, * — имя, ** — папки, завершающий / — вся папка.
Репозиторий → AI review: общий лимит diff 40 000–400 000 символов, default 160 000; на файл не больше четверти общего. Это лимит входного diff, не бюджет токенов модели. При сокращении не утверждайте, что просмотрены все изменения.
Отправка комментария к коду — запись Azure и требует Code Read & write. Просмотр обсуждений сам не отправляет сообщений.

В «Код репозитория → Коммиты» используется то же дерево и сравнение до/после, но без чтения и отправки комментариев. Первый коммит сравнивается с пустым деревом, merge-коммит — с первым родителем.

Окно diff имеет фиксированную высоту 85% экрана: переключение между короткими и длинными файлами не меняет размер попапа. Код и дерево прокручиваются внутри. На широком экране перетащите разделитель дерева вправо/влево или используйте стрелки, когда он в фокусе; ширина сохраняется в браузере и общая для PR/коммитов. На узком экране дерево располагается над кодом. Подсказка полного пути появляется сразу при наведении или фокусе.
История коммитов PR и репозитория оформлена одинаковыми компактными строками: сообщение, SHA, автор, дата. Нажатие строки открывает diff. Ветки в заголовке показаны синими бейджами: название закрывает историю и открывает нужную ветку в коде репозитория, соседняя кнопка копирует её имя.

Область дерева и сравнения растягивается до низа окна. Предупреждения о покрытии и пропусках доступны по жёлтой иконке в заголовке (наведение, фокус или нажатие). Рядом с хешем коммита кнопка копирует полный SHA, справа от пути файла — полный путь (для удалённого файла старый). Выбор языка обозначен иконкой кода без отдельной видимой подписи.

В истории коммитов PR название pull request показано в отдельном поле «Название pull request», как в окне Merge. Имена source/target-веток видны полностью: длинные значения переносятся без многоточия, переход к ветке и копирование сохраняются.

Справа от «View Diff» показан маленький бейдж количества изменённых файлов, справа от «Коммиты» — количества коммитов PR. Счётчик файлов учитывает уникальные пути, включая удалённые файлы, без папок и без фильтров AI-ревью. Подсчёт читает только списки Azure, не содержимое файлов и не запускает LLM. Он начинается при появлении карточки в области просмотра; результат кэшируется до следующего ручного обновления или синхронизации PR, без срока в пять минут. Повторное открытие страницы не обновляет счётчики само по себе. Для каждого PR хранится только текущая версия счётчиков; после обновления они запрашиваются заново. Кэш хранится в памяти сервера и очищается при его перезапуске. Это кэш счётчиков, а не содержимого diff.
«…» означает загрузку; «—» — ошибку, пояснение доступно при наведении. Ошибка счётчика не блокирует кнопки просмотра. Для очень больших PR после 20 страниц показывается нижняя оценка с «+», а не ошибочное точное число. Счётчики работают и у активных, и у завершённых PR.

## Подсветка TSX и JSX

Файлы .tsx и .jsx используют отдельную подсветку компонентов, свойств, строк и выражений внутри JSX. Она общая для кода репозитория, результатов поиска, diff коммитов и pull request. В diff выберите «Авто» или нужный режим «TypeScript / TSX» / «JavaScript / JSX»; обычные TypeScript и JavaScript доступны отдельно. Явно выбранный режим сохраняется, поэтому при ранее выбранном TypeScript переключите его на «Авто» для определения по расширению файла. В Markdown-сниппетах чата и памяти используйте метку языка tsx или jsx. Подсветка не меняет исходный текст, номера строк и копируемый код. Для неполных фрагментов diff контекста синтаксиса может не хватать; ограничения размера и возврат к обычному тексту сохраняются.

## Локальный кэш diff PR

Собранный View Diff сохраняется в локальной базе без таймера истечения. Повторное открытие, обновление страницы и перезапуск приложения используют тот же diff, пока не изменились source- или target-коммиты PR. Синхронизация либо кнопка «Обновить» у PR сначала актуализирует эти коммиты; если они прежние, diff повторно не скачивается. Само открытие View Diff не проверяет наличие новых пушей в Azure: для этого обновите PR. Изменение организации, проекта Azure, репозитория, исключений файлов или лимита diff также требует новой загрузки.

Хранится одна версия diff на PR; следующая заменяет предыдущую. При удалении локального PR (в том числе очистке завершённых через неделю) или проекта кэш удаляется вместе с ним. Одновременные открытия одной версии используют одну загрузку. Ошибка или прерывание загрузки не закрепляется в постоянном кэше; следующее открытие повторит попытку. Комментарии к строкам обновляются отдельно из Azure, а перед отправкой нового комментария версия PR проверяется заново. Кэш касается View Diff всего PR; просмотр отдельного коммита сохраняет прежнюю логику загрузки.

Подсветка в просмотре репозитория, поиске и diff вычисляется локально в фоновом обработчике браузера, без обращения к Azure или LLM. Если после обновления приложения TS/TSX и другие языки остались без цветов, перезагрузите страницу, чтобы загрузить актуальные обработчики подсветки; в diff также проверьте, что выбран «Авто», а не обычный текст.

## Полный файл из diff

Название выбранного файла над кодом в «View Diff» — ссылка в «Код репозитория». Она закрывает просмотр diff (и родительский список коммитов, если он открыт) и открывает полный файл, закреплённый за коммитом этого diff. Для удалённого файла открывается его версия до удаления, для переименованного — новый путь после переименования. Кнопка копирования пути остаётся отдельной.

Переход использует Git-подключение выбранного проекта: если оно не настроено или коммит недоступен локальному Git-сервису, страница кода покажет ошибку/указания по настройке; просмотр diff из Azure от этого не меняется. Для чужого контекста сначала выберите указанные заказчика и проект в хедере. Если в данных diff нет контекста проекта или точного коммита, название остаётся обычным текстом. Переход не меняет файлы и не создаёт комментарии.


## Файлы без текстового diff
Дерево показывает также пропущенные файлы из полученного списка изменений Azure: добавленные, удалённые, изменённые и переименованные. Значок предупреждения вместо количества строк означает, что содержимое не показано. При выборе файла справа указана причина: исключение настройками проекта, бинарный формат, размер более 50 000 символов, сложность diff, лимит размера/количества файлов или ошибка загрузки. Нулевые счётчики строк для таких файлов не показываются. Комментарий к строке без загруженного кода добавить нельзя.
Это работает и для diff отдельных коммитов. Лимиты загрузки сохраняются; если сам список Azure получен не полностью, дерево содержит только известные файлы, а предупреждение о неполном списке остаётся в заголовке.
При обновлении приложения старый кэш diff один раз пересобирается при открытии, чтобы получить сведения о пропущенных файлах. После успешной загрузки снова используется постоянный кэш. Ошибка загрузки не удаляет прежнюю сохранённую копию; следующее открытие повторяет попытку. Тикеты, привязки, ревью и настройки не изменяются.
