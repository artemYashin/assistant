# Настройки ассистента и моделей

## GitHub Copilot

Настройки → Copilot: подключение аккаунта через «Войти через GitHub» (GitHub CLI с одноразовым кодом), выбор модели чата и модели PR-ревью. Список моделей кэшируется на сутки; он зависит от доступности аккаунту. Подключение Azure PAT не подключает Copilot.
Собственное OAuth-приложение и Client ID больше не настраиваются; ранее сохранённый Client ID игнорируется.
Суточного ограничения количества PR-ревью в Orbit нет. Прежняя настройка убрана; сохранённое значение больше не действует. Лимиты времени, токенов и инструментов отдельного запуска настраиваются в Code Review.

## Провайдеры AI

В «Настройки → Провайдеры AI → Назначение моделей» поля «Провайдер чата» и
«Провайдер PR-ревью» независимы. Например, выберите «OpenAI-совместимый API» для
чата и оставьте «GitHub Copilot» для ревью. При обновлении оба поля по умолчанию
остаются Copilot. Возможность доступна в Lead и «Разработчик».

В разделе «OpenAI-совместимый API (необязательно)» задайте:

- «Адрес API»: HTTP(S) адрес сервера с нужным базовым путём, например
  `http://localhost:11434/v1`. Логин, пароль, параметры запроса и фрагмент в URL
  не допускаются. Адрес должен быть доступен с backend Orbit; в Docker
  `localhost` означает сам контейнер, а не компьютер пользователя.
- «Формат API»: Chat Completions либо Responses, который поддерживает сервер.
- «Ключ API»: ключ провайдера. Для локального сервера без авторизации поле можно
  оставить пустым. Ключ хранится в зашифрованном хранилище Orbit и не возвращается
  в форму. Пустое поле сохраняет прежний ключ; для удаления отметьте
  «Удалить сохранённый ключ API при сохранении». Чтобы заменить ключ, введите новый.
- «Модель внешнего API для чата» и «Модель внешнего API для PR-ревью»: точные
  идентификаторы моделей для соответствующих назначений. Имя можно ввести вручную
  или выбрать из подсказок после загрузки списка.

Кнопка «Сохранить и загрузить модели» сохраняет изменения всех вкладок, затем
загружает список из настроенного внешнего API. Модель заранее выбирать не нужно.
Нажмите на поле модели для подсказок или продолжайте вводить собственное имя:
наличие имени в списке не обязательно. Загрузка не выбирает первую модель и не
заменяет уже введённую. Один список доступен для чата и PR-ревью, выборы независимы.

Запрос списка использует сохранённый адрес и внешний ключ; GitHub-вход не нужен.
Это запрос каталога `/models`, без генерации ответа, истории или данных проекта.
Azure при этом не читается и не изменяется. Автоматической загрузки списка при
открытии приложения нет. Список хранится только в открытом интерфейсе; для
обновления нажмите кнопку снова. Изменение подключения или сохранение нового ключа
сбрасывает загруженные подсказки, но сохраняет введённые имена моделей.

Некоторые совместимые серверы не поддерживают `/models` или возвращают пустой
список. Ошибка загрузки не запрещает ручной ввод и не означает, что запросы к
самой модели недоступны. Если сохранение перед загрузкой прошло, настройки уже
действуют даже при ошибке списка. Проверьте адрес и ключ либо введите имя вручную.
Загрузка ограничена 10 секундами, размер ответа — 1 МиБ, список — 5000 моделями.
Наличие модели в каталоге не подтверждает поддержку инструментов или изображений.

Адрес, ключ и формат общие для двух назначений; модели выбираются отдельно.
Выбор внешнего API не стирает сохранённые модели и подключение Copilot.
Поля моделей на вкладке «Copilot» продолжают относиться только к Copilot,
в том числе наследование модели чата при пустой модели PR-ревью.

«Сохранить и проверить чат» и «Сохранить и проверить PR-ревью» сначала сохраняют
всю форму настроек, затем отправляют короткий проверочный запрос выбранному
провайдеру. Он может тарифицироваться; история, тикеты, память и код пользователя
в проверку не входят. Это проверка ответа модели, а не всех её возможностей.
Если проверка не удалась, настройки уже сохранены: исправьте адрес, формат,
ключ или модель и повторите. Отметка о сохранённом ключе не подтверждает его
валидность; Orbit не отслеживает срок действия внешнего ключа автоматически.

Для реальной работы модель должна поддерживать вызовы инструментов, а для
изображений — их чтение. Orbit не определяет эти возможности внешней модели
по каталогу Copilot. Лимиты контекста и особенности совместимости зависят от
провайдера. При работе внешняя модель получает контекст запроса и результаты
разрешённых инструментов; это может включать данные Azure, память и код.
Само сохранение подключения не изменяет Azure и не запускает ревью.
GitHub-вход для внешнего API не требуется; доступ к Azure настраивается отдельно.
Автоматического переключения на другой провайдер при ошибке нет.

Чат привязан к провайдеру, адресу и формату API. После их смены создайте новый чат
или верните прежние настройки для продолжения старого. История и результаты
инструментов не удаляются. Задания ревью также сохраняют привязку при запуске;
подробности — в [описании ревью](pr-review.md). Замена ключа того же подключения
не требует нового чата. Старые чаты и задания без новых полей считаются Copilot.
Обновление добавляет настройки с обратно совместимым чтением; таблицы, IDs,
история и прежние значения моделей не пересоздаются. Сохранение из старой
открытой вкладки без новых полей не сбрасывает выбор провайдера.

## AI Assistant → Общие настройки

Инструкции ассистенту дополняют поведение, но не отменяют обязательное UI-подтверждение памяти.
Лимит времени ответа — срок запроса чата (default 300 секунд). Максимум вызовов инструментов — default 30. Порог входных + выходных токенов чата на запрос — default 250 000, не размер полного контекстного окна модели и не месячная подписка.
Новое значение по умолчанию применяется, если лимит ещё не сохранён. Ранее сохранённое значение, включая 100 000, не меняется при обновлении; его можно изменить вручную.
Когда порог достигнут, ошибка указывает этот раздел настроек. Повышение бюджета увеличивает допустимые затраты; не лечит проблему доступа Azure.

## AI Assistant → Code Repository

«Доступ к коду» включён по умолчанию; при выключении кодовые инструменты не предоставляются. Ожидание подготовки Git — default 20 секунд, 0 не ждать, максимум 120; ограничено также общим временем ответа.
Основная ветка задаётся в настройках репозитория, не здесь. Явная просьба работать в другой ветке переопределяет её.

## Code Review

Лимит токенов ревью (default миллион) и инструментов (default 30) независимы от чата; общий бюджет на всё ревью/продолжения.

## Учёт

Входные токены включают доступный контекст, инструкции и результаты инструментов, которые модель читает; короткая пользовательская фраза не означает маленький вход. Повторные чтения и большой вывод инструментов могут увеличивать расход. SDK-usage может приходить с задержкой/частично; не путайте символы, токены и лимит окна модели.

Code Review → Лимиты ревью → «Лимит времени ответа ревью, секунд»: отдельный тайм-аут от 15 до 86 400 секунд, по умолчанию 600. Он включает запуск среды модели, ожидание модели и инструменты одного запроса; подготовка Git и сбор diff выполняются до него. После ответов на уточнения для следующего запроса время отсчитывается заново. Ошибка тайм-аута указывает соответствующий раздел настроек.

При анализе тикета полная деталка, уже прочитанная в текущем запросе, повторно используется инструментами get_ticket и list_tickets(detail=full). Это не постоянный кэш: следующий запрос может снова получить актуальные данные из Azure. Открытие деталки через show_ticket_details передаёт интерфейсу номера тикетов, без загрузки их содержимого в контекст модели.

## Режим работы

«Настройки → Рабочее пространство → Режим работы» определяет видимость локальных поручений и отпусков. В «Разработчик» их инструменты не предоставляются чату; остальные разрешения и лимиты чата/ревью продолжают действовать. Подробности: [Режим работы](work-mode.md).

Новый лимит времени чата 300 секунд применяется только при отсутствии сохранённого значения. Ранее заданные лимиты, включая 180 секунд, сохраняются; изменить их можно вручную в «AI Assistant → Общие настройки». Лимит ревью остаётся отдельным. Формат настроек не меняется, миграция данных не требуется.

## Ошибка сохранения перед подключением GitHub

Кнопка подключения GitHub сначала сохраняет форму настроек, затем начинает вход.
Если после обновления появлялась ошибка «Проверьте поля формы» с `unrecognized_keys`
для `kanbanStateOrder` или других `kanban…`, обновите Orbit и повторите подключение.
Общие настройки больше не отправляют поля канбана, а сервер принимает такие поля
от уже открытых старых вкладок без изменения настроек проекта. Пересоздавать проект,
сбрасывать настройки или удалять токены не нужно. Остальные поля по-прежнему проверяются;
при другой ошибке исправьте указанное значение. Настройки колонок и групп сохраняются
отдельно в «Заказчики и проекты → Канбан».
