# Azure: подключение и PAT

## Где задавать значения
Настройки → Azure DevOps: Personal Access Token, версия REST API и фоновая синхронизация. Фильтры автоимпорта и цвета перенесены в «Заказчики и проекты» → «Автоматический импорт».
Хедер → Заказчики и проекты → Подключение Azure: глобальные параметры организации/коллекции и выбранный Azure-проект. «Использовать глобальные настройки Azure» включает наследование. Поля наследуемых значений видны, но недоступны для ручного изменения; для собственного подключения снимите галочку.
В поле URL организации не вставляйте полный URL отдельного тикета или /_git/. Azure-проект — отдельное поле. Для dev.azure.com структура: организация / проект / _git / репозиторий. Пробелы проекта кодируются приложением при запросах; вводите название проекта, а не случайный другой сегмент ссылки.
Корпоративный адрес с .mcas. может быть прокси браузера, не исходным REST-адресом. Не обходите политику компании; проверьте разрешённый API endpoint.
Git-репозиторий задаётся отдельно: Заказчики и проекты → Репозиторий → Git, точное имя или ID.
## Права PAT по функциям
- Work Items · Read: импорт, детали, комментарии/вложения, связанные тикеты.
- Work Items · Read & write: изменение статуса/исполнителя, в том числе при merge.
- Code · Read: PR, diff, коммиты, обсуждения, загрузка Git и поиск кода.
- Code · Read & write: создание/слияние PR, Abandon, Draft, комментарии к коду.
- Build · Read: этапы CI и логи выбранного шага; запуск пайплайнов не нужен.
- Graph · Read: поиск пользователей по части имени для выбора исполнителя и ревьюеров.
- Identity · Read: поиск и сопоставление Azure-пользователей с идентификаторами для назначения.
Full access не требуется. Права PAT не заменяют права пользователя на конкретный проект, репозиторий и сборки; bypass policies — отдельное право Azure.
Локальные заметки, теги и память не требуют Azure write. Copilot подключается отдельно.
## Проверка ошибок
401/403: срок PAT, scopes, доступ самого аккаунта. 400/404: URL, Azure-проект, имя/ID репозитория и версия API; код сам по себе не доказывает, какое поле неверно.
Не присылайте PAT в чат. Можно сообщить текст ошибки, endpoint без секретов и reference-код.

## Каталог типов и статусов для автоимпорта
Во вкладке «Заказчики и проекты» → «Автоматический импорт», в блоке «Автоматически импортировать мои задачи» полный список загружается автоматически при открытии настроек: из кэша, а при его отсутствии или истечении 30 дней — из Azure. Галочки управляют только фильтром, не полнотой каталога. Правая колонка показывает статусы выбранных типов; сохранённые выбранные статусы и цвета применяются к показанным типам и статусам.
«Реимпортировать статусы» принудительно обновляет типы и их статусы, не сохраняет остальные настройки и не сбрасывает галочки/цвета. Используется сохранённое подключение: если изменили PAT или подключение, сначала сохраните его. При ошибке показывается сообщение, прежний список в форме остаётся. Настройки фильтров сохраняются кнопкой «Сохранить» только для выбранного проекта.

## Срок токена Azure DevOps

В «Настройки → Azure DevOps → Подключение и доступ» рядом с PAT задайте «Дата истечения PAT» и сохраните настройки. Дата выбирается тем же календариком, что и даты напоминаний. Срок указывается вручную: Orbit не проверяет фактическую дату истечения токена в Azure. Начало выбранного дня (00:00) трактуется как истечение, в часовом поясе календаря.

Если PAT сохранён и дата указана, в календаре и списке напоминаний появляется одна общая служебная запись «Истекает токен Azure DevOps». Она не зависит от выбранного заказчика или проекта. За 7 суток до срока запись начинает показываться в колокольчике и его счётчике; затем остаётся и после истечения срока. Повторные всплывающие и браузерные уведомления используют общий интервал и расписание календаря, а системные уведомления требуют разрешения браузера. До начала недельного предупреждения в колокольчике её нет.

Это обязательное предупреждение: нет скрытия из календаря/уведомлений, завершения, удаления, переноса перетаскиванием или настройки другого интервала. Во всплывающем блоке у него нет крестика и завершения; «Закрыть все уведомления» сохраняет это предупреждение. Из деталки можно только прочитать данные и закрыть окно. При замене PAT обновите дату в настройках: запись обновится без дубликата, прежнее предупреждение исчезнет, если новый срок дальше недели. Дату после первой настройки можно заменить, но нельзя очистить для скрытия уведомления. Пустое поле PAT сохраняет прежний токен; изменение одной даты не заменяет токен.

При обновлении приложения существующие токены, настройки и напоминания сохраняются. Для старого PAT срок неизвестен, поэтому дата по умолчанию пустая, предупреждение не создаётся до её настройки. Старые клиенты, не передающие поле даты при сохранении настроек, не стирают сохранённый срок. Некорректная дата не сохраняется и не заменяет токен.

Инструменты календаря ассистента видят служебную запись с systemKind=azure_pat, но не могут её изменить, скрыть, завершить или удалить. При массовых действиях ассистент должен исключать такие записи и направлять пользователя в настройки Azure DevOps. Сам токен в напоминание и результаты поиска не попадает.
