# Разработчики и поручения

## Настройка
Заказчики и проекты → Разработчики: заведите локальный список людей с уровнем «Общий», «Заказчик» или «Проект». Это не Azure Directory и не смена Azure AssignedTo. Назначайте их тикетам в локальном поле поручения.
Группы статусов определяют, какие задачи считаются активными, на проверке и завершёнными. Изменение группировки не меняет статус в Azure.
## Страница Разработчики
Карточка человека показывает его поручения; раскрытие открывает вкладки «Активные», «На проверке», «Завершённые» со счётчиками. Есть просмотр без назначенного исполнителя. Внутри — пагинация по пять тикетов.
Заметки разработчика редактируются в небольшом текстовом поле «Заметки» внутри попапа «Настройки»; «Сохранить заметки» сохраняет текст только в текущем проекте. Статусы/тип и приоритет тикета видны в карточке.
## Тикет
Каждый тикет имеет рамку и фон. Кнопка с названием открывает деталку в попапе без перехода в Azure. Слева иконка ссылки копирует Azure URL; успех/ошибка копирования отображается рядом. Номер и название идут без разделяющей точки.
В завершённую группу могут входить локально сохранённые данные; не считайте её проверкой текущего Azure в реальном времени. Для актуализации используйте синхронизацию тикетов.

В меню «Заказчики и проекты» → «Разработчики» аватар, имя и две кнопки расположены в одной строке. Крестик убирает разработчика из справочника, кнопка с дискетой «Сохранить имя и уровень» сохраняет изменённое имя и выбранный уровень. Настройки «Группировка поручений» открываются нажатием на любую часть компактной строки заголовка; отступы для содержимого появляются внутри раскрытого блока.

В «Группировке поручений» статусы отображаются такими же бейджами и с теми же настроенными цветами, что и в таблице тикетов. Таблица имеет внешнюю рамку, разделители и подсветку выбранной группы. Заголовки столбцов закреплены при прокрутке таблицы. На верхнем и нижнем краю таблицы дальнейшая прокрутка колесом передаётся всему попапу. Цвет сам по себе не меняет группировку или статус Azure.


## Уровни доступности
В «Заказчики и проекты» → «Разработчики» список разделён на группы:
- «Общий · все проекты» — доступен во всей системе.
- «Заказчик · название» — доступен во всех проектах этого заказчика.
- «Проект · название» — доступен только выбранному проекту.

Перед добавлением выберите «Уровень нового разработчика» и введите имена, по одному на строку. Без выбранного заказчика доступен общий список; с заказчиком можно вести его список без выбора проекта.

Чтобы сделать существующего разработчика доступным в других проектах, поменяйте уровень в его строке и нажмите дискету «Сохранить имя и уровень». ID человека и существующие назначения сохраняются; дубликат автоматически не создаётся. Совпадение имени внутри целевого уровня отклоняется: записи с одинаковыми именами автоматически не объединяются. Разработчики из разных уровней могут иметь одинаковые имена и разные ID.

Изменение имени и удаление из общего/клиентского справочника действует во всех проектах, где этот разработчик доступен. Удаление скрывает его из новых назначений, но сохраняет существующие поручения. При сужении уровня старые поручения также сохраняются. Ранее сохранённые заметки и группировка поручений остаются проектными. При удалении проекта общие разработчики и разработчики заказчика сохраняются. Существующие разработчики проекта не меняют уровень автоматически.

Список разработчиков полностью локальный: вкладка не загружает пользователей Azure и не добавляет владельца PAT. Иерархия показывает ранее сохранённые общие записи; старая миграция переносила существовавшие локальные назначения в общий справочник. Пользователи, выбранные для автоимпорта, сюда не попадают. Группы имеют отдельные рамки; список использует общую прокрутку окна, чтобы внутренний контейнер не обрезал выбор уровня.

## Работа через чат
Инструмент `list_local_developers` возвращает всех доступных разработчиков: общих, текущего заказчика и текущего проекта. Поля `client` и `project` показывают уровень записи; отдельный фильтр уровня не требуется. По номеру тикета инструмент также читает его текущие локальные поручения. `set_local_ticket_developers` назначает людей по ID только по явной просьбе пользователя. При добавлении или снятии одного поручения ассистент должен прочитать текущий список и сохранить остальных. Существующее поручение не исчезает после переноса разработчика в другой уровень; оно по-прежнему доступно в текущих назначениях тикета. Инструменты не обращаются к Azure.


## Отпуска и настройки разработчика
Рядом с именем отображается уровень: «Общий список», «Заказчик · название» или «Проект · заказчик / проект». Кнопка «Настройки» заменила «Заметки». В ней можно задать «Отпуск с» и «Отпуск по» включительно, сохранить период или нажать «Отменить отпуск». Один разработчик имеет один период, общий для всех проектов, где он доступен. Изменение дат заменяет период, а не добавляет новый отпуск. Нельзя сохранить окончание раньше начала или только одну дату.

Пока идёт отпуск, разработчик исключён из вкладок «С активными задачами» и «Без активных задач», включая их счётчики. Он остаётся во вкладках «Все» и «В отпуске». Запланированный отпуск пока не исключает человека из обычных групп. После последнего дня отпуска он автоматически возвращается в группы по своим поручениям. Даты определяются в часовом поясе, выбранном при первом сохранении отпуска; смена общей настройки не сдвигает существующий период. В карточке показана дата возвращения — следующий календарный день после «по».

Заметки не удаляются при обновлении: прежний текст сразу доступен для редактирования в поле «Заметки» в настройках разработчика. Существующие поручения, имя и ID разработчика сохраняются. Отпуск не меняет назначение или статус тикетов и не вызывает Azure.

В календаре появляется одно связанное событие типа «Отпуск». Подробности: [Отпуска разработчиков](developer-vacations.md).

Отпуск можно задать, продлить или отменить просьбой к чат-ассистенту: он использует `set_developer_vacation` после проверки списка и текущего периода. В «Настройках» выбор дат — общий календарный компонент без часов и минут. Бейдж уровня рядом с именем занимает ширину своего текста.


## Скоро в отпуск
Вкладка «Скоро в отпуск» показывает доступных разработчиков, чей отпуск ещё не начался, но уже наступил интервал «Предупреждать об отпуске разработчика за» из настроек календаря. Счётчик использует тот же интервал. При нулевом интервале вкладка пуста. Поиск по имени применяется и к этой вкладке, и к её счётчику. В карточке показаны даты отпуска включительно и возвращение (следующий день после окончания).

Будущий отпуск не исключает человека из вкладок по активным задачам. В начале отпуска, по сохранённому часовому поясу, человек автоматически исчезает из «Скоро в отпуск» и попадает во «В отпуске». При открытой странице состояние обновляется по минутному таймеру и после возвращения фокуса без перезагрузки. Отменённые, текущие и закончившиеся отпуска в будущую выборку не входят. Изменение дат в настройках или чате обновляет список.

Ассистент использует `list_local_developers` с `vacationStatus: "upcoming"`. Также доступны `current` (в отпуске), `past` (период закончился), `none` (период не задан), `all` или отсутствие параметра (прежний полный список). Возвращаются даты, часовой пояс, `vacationStatus` и `returnDate`; фильтр действует на доступных разработчиков текущего проекта, заказчика и общего списка. Если указан `ticketId`, его текущие поручения в `assigned` возвращаются полностью, независимо от фильтра списка.

## Отпуск при назначении тикета

В попапе «Локальное поручение» рядом с разработчиком, который сейчас в отпуске, показывается пометка «В отпуске · Возвращение» с датой возвращения. Даты отпуска включительны и учитывают его часовой пояс; возвращение — следующий календарный день после окончания. Список актуализируется при открытии попапа, в том числе для уже выбранных исполнителей. Для будущего отпуска показывается «Скоро в отпуск · Уход … · Возвращение …». В попапе эта пометка появляется только внутри интервала из «Настройки → Календарь → Предупреждать об отпуске разработчика за»: начало отпуска в 00:00 его часового пояса минус заданное число дней, часов и минут. Например, семь дней — ровно 168 часов до начала. При нулевом интервале предварительной пометки нет. Настройка перечитывается при открытии попапа. Индивидуальное предупреждение события и скрытие его из уведомлений не меняют эту подсказку при назначении. Вкладка «Скоро в отпуск» и её счётчик в разделе разработчиков используют этот же интервал. В день начала пометка становится «В отпуске» при следующем открытии попапа. Закончившийся отпуск не отмечается. Дата возвращения не переносится с выходного на рабочий день. Это предупреждение: выбрать человека и сохранить поручение всё равно можно. Azure и существующие поручения не меняются без сохранения.

## Режим работы

Раздел и вкладка настроек разработчиков доступны в Lead. Режим «Разработчик» скрывает их вместе с локальными поручениями, но не удаляет справочник, назначения или группировку статусов. Подробности: [Режим работы](work-mode.md).


«Сохранить заметки» сохраняет до 20 000 символов обычного текста отдельно от отпуска. Чтобы очистить заметку, удалите текст и сохраните. Изменение отпуска не сохраняет черновик заметки и наоборот. При ошибке сохранения текст остаётся в поле: повторите сохранение; закрытие без сохранения не записывает изменения в базу. Заметки относятся к текущему проекту, в том числе для разработчиков из общего списка или списка заказчика. В Azure ничего не отправляется. Используется прежнее хранилище заметок без переноса или сброса данных.
