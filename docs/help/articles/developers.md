# Разработчики и поручения

## Настройка
Заказчики и проекты → Разработчики: заведите локальный список людей с уровнем «Общий», «Заказчик» или «Проект». Это не Azure Directory и не смена Azure AssignedTo. Назначайте их тикетам в локальном поле поручения.
Группы статусов определяют, какие задачи считаются активными, на проверке и завершёнными. Изменение группировки не меняет статус в Azure.
## Страница Разработчики
Карточка человека показывает его поручения; раскрытие открывает вкладки «Активные», «На проверке», «Завершённые» со счётчиками. Есть просмотр без назначенного исполнителя. Внутри — пагинация по пять тикетов.
Заметки разработчика открываются отдельной кнопкой; «Сохранить заметки» сохраняет текст только в текущем проекте. Статусы/тип и приоритет тикета видны в карточке.
## Тикет
Каждый тикет имеет рамку и фон. Кнопка с названием открывает деталку в попапе без перехода в Azure. Слева иконка ссылки копирует Azure URL; успех/ошибка копирования отображается рядом. Номер и название идут без разделяющей точки.
В завершённую группу могут входить локально сохранённые данные; не считайте её проверкой текущего Azure в реальном времени. Для актуализации используйте синхронизацию тикетов.

В меню «Заказчики и проекты» → «Разработчики» аватар, имя и две кнопки расположены в одной строке. Крестик убирает разработчика из справочника, кнопка с дискетой «Сохранить имя и уровень» сохраняет изменённое имя и выбранный уровень. Настройки «Группировка поручений» открываются нажатием на любую часть компактной строки заголовка; отступы для содержимого появляются внутри раскрытого блока.

В «Группировке поручений» статусы отображаются такими же бейджами и с теми же настроенными цветами, что и в таблице тикетов. Таблица имеет внешнюю рамку, разделители и подсветку выбранной группы. Цвет сам по себе не меняет группировку или статус Azure.


## Уровни доступности
В «Заказчики и проекты» → «Разработчики» список разделён на группы:
- «Общий · все проекты» — доступен во всей системе.
- «Заказчик · название» — доступен во всех проектах этого заказчика.
- «Проект · название» — доступен только выбранному проекту.

Перед добавлением выберите «Уровень нового разработчика» и введите имена, по одному на строку. Без выбранного заказчика доступен общий список; с заказчиком можно вести его список без выбора проекта.

Чтобы сделать существующего разработчика доступным в других проектах, поменяйте уровень в его строке и нажмите дискету «Сохранить имя и уровень». ID человека и существующие назначения сохраняются; дубликат автоматически не создаётся. Совпадение имени внутри целевого уровня отклоняется: записи с одинаковыми именами автоматически не объединяются. Разработчики из разных уровней могут иметь одинаковые имена и разные ID.

Изменение имени и удаление из общего/клиентского справочника действует во всех проектах, где этот разработчик доступен. Удаление скрывает его из новых назначений, но сохраняет существующие поручения. При сужении уровня старые поручения также сохраняются. Заметки и группировка поручений остаются проектными. При удалении проекта общие разработчики и разработчики заказчика сохраняются. Существующие разработчики проекта не меняют уровень автоматически.
