# CI, конфликты и Merge

## Проверки

Бейдж конфликтов и бейдж CI открывают разные попапы. Отсутствие конфликтов не равно успешному CI.
CI-попап показывает проверки/сборку, этапы и справа лог выбранного шага. Логи не загружаются постоянно вместе со списком PR; нужны Build Read и доступ к сборке. Не считайте логи безопасными для публикации: сторонние pipeline scripts могут писать чувствительные значения.
Ожидающий или выполняющийся CI больше не блокирует кнопку Merge и отправку запроса слияния в Orbit. Azure по-прежнему применяет собственные политики; обход не включается автоматически. Если CI завершился с ошибкой, Merge недоступен; tooltip объясняет причину. Отсутствие настроенного CI и неизвестное состояние из-за ошибки доступа — разные случаи. Не обходите неизвестные проверки автоматически.

## Merge

Форма повторяет название и source → target, показывает актуальный план. При каждом открытии «Способ слияния» пуст («Выберите…»): явно выберите стратегию из выпадающего списка. Пока она не выбрана, «Подтвердить merge» недоступна, в том числе при обходе политик. Предыдущий выбор не запоминается. Условия и доступные стратегии определяет Azure.
Обход проверок/политик — явная опция, при необходимости причина; требует соответствующего права, а не только PAT. Не рекомендуйте его как обычное лечение CI-ошибки.
«Сменить статус связанных тикетов» показывает учитываемые ID и текущие/новые статусы с настроенными цветами. Выберите каждому значение или «Не менять статус», можно применить общий статус. Локально исключённые связи не включаются.

## Изменившийся план и ошибки

Если ветки, связи или условия изменились после открытия, план может потребовать обновления. Слияние и смена статусов — не единая атомарная операция Azure: возможен успешный merge с отдельными неудачными изменениями тикетов. Смотрите результат по каждому пункту, не повторяйте успешные записи вслепую.
Кнопка merge не ставит auto-complete. Не путайте Abandon со слиянием.
