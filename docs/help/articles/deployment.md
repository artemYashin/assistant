# Docker и локальные данные

Orbit работает вместе с отдельными voice и code-browser сервисами согласно compose.yaml. Node-бэкенд хранит локальную SQLite-базу и секреты в каталоге данных; Git-сервис имеет отдельное хранилище кода.
Docker build использует npm ci для воспроизводимой установки зависимостей по lockfile. Python/make/g++ нужны стадии сборки native-модулей; это не установка при каждом открытии страницы. Изменение базового образа/зависимостей/слоёв или очистка Docker-кэша может сделать rebuild медленным.
Обычный git pull обновляет исходники, но не пересобирает уже работающий образ автоматически. Выполняйте принятый процесс обновления compose; не удаляйте папки данных ради обновления интерфейса.
Данные/ключ шифрования должны сохраняться вместе. Потеря ключа не лечится новым PAT для всех старых секретов. Не публикуйте .env, базу и master.key.
Справка docs/help поставляется в runtime-образе. После обновления приложения сервер получает соответствующую версию статей; изменение MD в исходниках требует доставки в контейнер/перезапуска.
Если контейнеры приостановлены при сне Mac, фоновая синхронизация и загрузка тоже не продвигаются. Сверяйтесь со статусом сервиса и текущей работы, а не только с процентом.

## Папки Docker и первый запуск

Compose хранит данные в docker-data/ внутри проекта: orbit — база, master.key и данные Orbit; repositories — Git-кэш; repo-control — внутренний ключ сервисов; whisper — модели голоса. Эти папки исключены из Git и контекста Docker build. Пути фиксированы относительно compose.yaml, а не текущей папки терминала.
Для новой установки без данных используйте `bash scripts/first-start.sh`: скрипт создаёт папки с правами сервисов, собирает и запускает приложение. Существующие папки не перезаписываются. Не меняйте владельцев всех папок на одного пользователя: Orbit/Git используют UID 1000, voice — UID 10001.
Для обновления из папки проекта выполните `docker compose stop && git pull --ff-only && docker compose up --build -d`. При ошибке следующий шаг не выполняется. После ошибки сборки устраните причину и повторите `docker compose up --build -d`, не инициализируя данные заново.

## Резервная копия

Остановите сервисы и скопируйте docker-data целиком, сохраняя права и симлинки. База и master.key должны быть в одной резервной копии. После проверки копии запустите `docker compose up -d`. Для восстановления сначала сохраните текущие данные отдельно; не смешивайте файлы разных копий. Клон проекта в соседней папке не получает данные существующей установки автоматически. Подробности — docs/DOCKER_STORAGE.md.

## Установщики и обновление

Из уже скачанного проекта запустите `bash install.sh` на macOS/Linux или
`powershell -ExecutionPolicy Bypass -File .\install.ps1` на Windows.
Клонирования нет. Windows использует WSL (по умолчанию Ubuntu); после установки WSL
может потребоваться перезагрузка и повтор команды. Работающий локальный Docker
используется без переустановки. Новая установка Rancher включает Moby и выключает
Kubernetes. Автоматическая установка Linux поддерживает Debian/Ubuntu с графической
сессией и доступом к /dev/kvm; остальные дистрибутивы требуют готового движка.
Уже установленный, но остановленный движок нужно запустить самостоятельно.
Повторный запуск использует существующие папки данных; неполный набор не перезаписывается.

`bash update.sh` (Windows: в WSL) проверяет чистоту Git, upstream и Docker, затем
останавливает контейнеры, обновляет текущую ветку без merge-коммита и пересобирает их.
Скрипты подтверждают запуск ссылкой http://localhost:43871 только после успешной
проверки здоровья Orbit. При ошибке показывается диагностика без сообщения об успехе.
Если pull не удался, `docker compose start` возвращает старые контейнеры;
после ошибки сборки повторите `docker compose up --build -d`. Данные не сбрасываются.
Подробные требования и команды — GETTING_STARTED.md.
