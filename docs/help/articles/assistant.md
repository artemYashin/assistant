# Чат-ассистент

## Панель
Хедер показывает заказчика/проект, название чата, расход входящих/исходящих токенов и доступные сведения о контексте. «Чаты» открывает историю по группам сегодня/вчера/неделя; длинные названия сокращаются визуально. Выберите чат для продолжения или начните новый. Рядом с каждым названием есть красная кнопка-корзина: она открывает подтверждение «Удалить чат?». «Отмена» ничего не меняет; «Удалить чат» удаляет сам чат, сообщения и его историю инструментов без возможности восстановления. Сохранённая память и общий учёт токенов сохраняются. При удалении текущего чата открывается другой сохранённый; если удалён последний — создаётся новый пустой. Во время ответа ассистента удаление недоступно: дождитесь окончания или остановите ответ.
Внизу поле сообщения, очистка черновика крестиком, удаление/очистка чата с confirmation, выбор модели, микрофон и отправка. Во время ответа вместо отправки/микрофона — остановка. Остановка не откатывает уже выполненные внешние действия.
## Ответ в процессе
Текст выводится потоково; промежуточные сообщения и вызовы инструментов остаются в истории. Инструменты имеют статус и длительность; общий таймер показывает время запроса.
История вызовов открывается отдельным попапом: слева список, справа параметры и результат, переключение полного/краткого. Полный результат включён по умолчанию. Токены показываются по доступным SDK-данным, а не по числу символов. Не приписывайте каждому инструменту точную стоимость модели, если такой детализации нет.
## Контекст
История и результаты используются в рамках выбранного чата; не предполагайте объединение всех прошлых чатов. Деталка/Analyze и Refine добавляют видимый бейдж следующему сообщению. Крестик снимает вложение. После отправки бейдж остаётся при сообщении, не должен висеть у ввода.
## Возможности
Поиск/сортировка локальных тикетов, заметок/описаний, чтение ссылок/изображений, открытие деталок, локальные изменения, PR-списки/сохранённое ревью, чтение кода и предложения памяти. Полные схемы подключаются через load_tools только при необходимости.
Для простого списка выбираются минимальные поля. Подробное чтение кэша до 30 разных тикетов за запрос не требует предупреждения; дальше — согласие. Отдельные live Azure-чтения имеют свои правила. Синхронизация — только по явной просьбе, не перед каждым поиском.
## Помощь
«Помоги с приложением» подставляет стартовый запрос; отправьте его. Для подробных вопросов о функциях/ошибках ассистент ищет эту справку и читает выбранные статьи. «Что ты умеешь?» не требует загрузки документации.

## Импорт списка тикетов
Попросите «Импортируй тикеты #123, #456» или передайте ссылки Azure на нужные задачи. Ассистент использует одиночный импорт либо пакетный инструмент до 50 операций за вызов; большие списки разбивает на пакеты. Повторное подтверждение явной команды импорта не требуется. Тикеты загружаются из текущего Azure-проекта и сохраняются локально; задачи из другого проекта отклоняются, поля Azure не изменяются. Импорт может восстановить тикет из корзины. Результат содержит успехи и ошибки по номерам, а не полные описания; частичный успех не означает, что импортированы все. Таблица обновляется после импорта. Обычный поиск или просьба показать тикеты сами по себе не разрешают импорт.

## Подготовка Excel/CSV
Ассистент может открыть форму экспорта с локальными ID инструментом `show_ticket_export` и редактировать открытый или свёрнутый список через `edit_ticket_export`: добавлять и удалять тикеты, менять столбцы. Это не импорт и не скачивание: пользователь сам выбирает формат, столбцы и нажимает кнопку скачивания. Вызов возвращает только номера, включая отсутствующие локально; описания тикетов не загружаются в контекст. Не затронутые командой тикеты сохраняются; удаление из экспорта не удаляет тикет из системы.
Ассистент видит только отметку об открытом или свёрнутом экспорте. Краткие карточки выбранных тикетов в таблице или экспорте читает по необходимости через `read_selected_tickets` (по 100 карточек: ID, название, статус и тип; дополнительные поля, включая теги, через `fields`); поля и формат экспорта доступны в этом же инструменте. Списки не добавляются автоматически в контекст модели, закрытый экспорт не передаётся. По запросу он может включить нужные столбцы и расположить их в заданном порядке; изменение полей не заменяет набор тикетов. Открытие/добавление без указания столбцов сохраняет их текущие настройки.

Поиск тикетов (`list_tickets`) и поиск по содержимому (`search_ticket_content`) принимают несколько типов и Azure-статусов за один вызов. Например, `type: ["Bug", "Task"], state: ["New", "Active"]` означает Bug **или** Task, находящиеся в New **или** Active. Между типом, статусом и остальными фильтрами действует **И**. Сравнение точное, с тем же правилом нечувствительности к регистру, что у одиночного фильтра; доступные значения ассистент получает через `get_ticket_catalog`. Пустой массив или отсутствие поля не ограничивает выборку по этому полю. Одиночные строки поддерживаются для совместимости. Сортировка и пагинация применяются ко всей объединённой выборке; это локальный поиск без Azure.

Фильтры `tag` (локальные теги), `azureTag` (Azure-теги) и `priority` (локальные приоритеты) также принимают массивы в поиске тикетов и содержимого. Например, `tag: ["backend", "urgent"], priority: [1, 2]` выбирает тикеты хотя бы с одним из тегов и с приоритетом 1 или 2. Разные поля объединяются через И; пустой массив не ограничивает выборку. Одиночные строки тегов и число приоритета по-прежнему поддерживаются.

Поиск текста поддерживает `searchMode: "literal"` (по умолчанию) и `searchMode: "regex"`. В `list_tickets` шаблон ищется в названии и Azure-тегах, в `search_ticket_content` — в кэшированных описании, критериях, шагах воспроизведения и локальных заметках. Например, `search: "login|auth", searchMode: "regex"` ищет оба варианта одним вызовом. Регулярки RE2 задаются без обрамления `/…/`, без обратных ссылок и lookaround; поддерживаются группы, альтернативы, классы символов, `^` и `$` (границы строк). Поиск без учёта регистра. Массивы фильтров, сортировка и пагинация продолжают работать. Короткие фрагменты не превращаются в полные описания, даже если шаблон захватил много текста. Неверный или слишком сложный шаблон возвращает понятную ошибку: исправьте выражение либо вернитесь к `literal`. Это сопоставление текста, не семантический поиск.

## Полнота результатов инструментов
Общая обёртка инструментов передаёт результат в SDK целиком: автоматического обрезания после 24 000 символов нет. Это относится также к инструментам ревью, использующим общую обёртку. Пагинация, выбор полей и диапазоны чтения отдельных инструментов сохраняются; следующие страницы модель запрашивает отдельно. Настроенные лимиты токенов и размер контекста модели продолжают действовать. Сокращённый текст в диагностическом журнале не означает, что результат для модели был сокращён.

## Файлы в сообщении
Плюс «Добавить вложения» в нижней строке чата открывает системное окно выбора файлов; при наведении кнопка подсвечивается зелёным. Поддерживаются картинки PNG, JPEG, GIF и WebP, а также TXT, Markdown (.md, .markdown), CSV и JSON в UTF-8. PDF и Excel пока не поддерживаются. Выберите до 6 файлов: каждый не больше 10 МБ, все вместе — до 30 МБ. Текстовый файл должен быть не больше 200 000 символов; превышение отклоняется, содержимое не обрезается.
Между текстовым полем и кнопками появляются компактные карточки по ширине содержимого, в строку с переносом: «Вложение 1», «Вложение 2» и далее, имя файла, маленькая миниатюра картинки и крестик удаления. Длинное имя сокращается с начала; полное видно при наведении. Весь бейджик картинки, включая номер, имя и миниатюру, кликабелен и подсвечивается при наведении. Клик открывает стандартный попап просмотра изображения с масштабированием и перемещением; Esc закрывает его. Просмотр работает сразу, до отправки файла. Крестик только удаляет вложение и не открывает просмотр; бейджики текстовых файлов не открывают превью. После удаления номера пересчитываются. Нумерация относится к вложениям конкретного сообщения и сохраняется рядом с отправленным сообщением; можно спросить «что на третьей картинке?» или «сравни вложения 1 и 2».
При отправке Orbit сохраняет файлы в текущем чате, сразу передаёт картинки модели через SDK, а текстовые файлы — полным содержимым. Модель получает указание прочитать все вложения до ответа; отдельная просьба вызвать инструмент чтения не нужна. Для изображений требуется модель с vision; несовместимая модель или превышение её числа изображений дают ошибку. Файлы потребляют контекст и токены, поэтому действуют обычные лимиты чата и модели. Вложение не означает импорт тикетов или загрузку файла в Azure.
Голосовое сообщение в текущий чат использует тот же список вложений. При отправке список сразу очищается; при ошибке файлы возвращаются к полю ввода, уже сохранённые файлы повторно не загружаются. Можно отправить одни файлы без текста — запрос будет «Прочитай все приложенные файлы.». Несохранённые черновики разделены по чатам и живут до перезагрузки страницы; в другом чате чужие вложения не отправляются.
Отправленные файлы хранятся в локальной базе с привязкой к чату; очистка истории или удаление чата удаляет их локальные копии. Неиспользованные загрузки старше суток очищаются при следующей загрузке файла. Содержимое прочитанных вложений сохраняется в сессии SDK для продолжения разговора. Если содержимое прочитать нельзя, ассистент должен сообщить об этом, а не утверждать, что прочитал файл.

Файлы можно перетащить на весь белый блок ввода чата, включая нижние кнопки. При наведении появляется оверлей «Drop your files here»; отпускание добавляет вложения к черновику, но не отправляет их. Пока ассистент отвечает, история очищается или чат ещё не выбран, добавление недоступно. Перетаскивание обычного текста остаётся обычным редактированием.
Неподдерживаемое расширение, пустой файл, превышение 10 МБ на файл, 30 МБ на набор или 6 вложений открывают попап «Не удалось добавить вложения» со списком поддерживаемых расширений. Это одинаково работает при перетаскивании и выборе через плюс. Весь новый набор отклоняется, ранее прикреплённые файлы остаются. Закройте попап кнопкой «Понятно», уберите неподходящие файлы и повторите добавление.

Чтобы добавить скриншот из буфера, установите курсор в поле сообщения и нажмите Ctrl+V (на macOS — Cmd+V). Картинка сразу появится в нумерованном списке вложений с миниатюрой; отправка начнётся только вместе с сообщением. Действуют те же проверки формата, размера и количества, что для перетаскивания и кнопки «Добавить вложения», ошибки показываются в том же попапе. Обычный текст вставляется как раньше; если в буфере одновременно есть текст и картинка, текст вставляется в поле, а картинка прикрепляется. Во время ответа ассистента добавление картинок недоступно.

## Прочитать картинку по ссылке
По просьбе «прочитай эту картинку» или «что на скриншоте рядом с …» ассистент может загрузить изображение инструментом `read_image`. Он выбирает URL из контекста разговора или ссылок тикета; если непонятно, какую картинку вы имели в виду, должен уточнить. Простое наличие ссылки или изображения в описании тикета не разрешает автоматический просмотр. Загруженные пиксели передаются в текущую сессию модели как нативное вложение; результат не заменяется пересказом URL.

Поддерживаются прямые публичные HTTPS-ссылки без перенаправлений и авторизации, изображения тикетов/PR через ссылки Orbit и вложения Azure текущего подключения. Для Azure используется настроенный PAT; сторонним сайтам он не передаётся. Ссылки на локальную сеть и служебные адреса не поддерживаются. Лимит — 10 МБ, форматы PNG/JPEG/GIF/WebP. Нужна модель с поддержкой изображений. Недоступный URL, страница вместо картинки, неподдерживаемый формат и превышение размера дают ошибку, а не «прочитанное» изображение.

На изображениях справа сверху есть «Скопировать ссылку на изображение» и «Прикрепить изображение к чату» (звёздочка); те же действия доступны в большом просмотрщике. Для маленьких миниатюр уже прикреплённых файлов действия находятся в открытом просмотрщике. Копирование сохраняет полный внешний URL: для вложения тикета — прямой адрес Azure, для PR и внешних изображений — исходную ссылку. Внутренние адреса /api/ticket-cards не копируются. У локальных файлов чата, blob/data-изображений и незагруженных картинок черновика кнопка отключена: внешней ссылки ещё нет. При получении адреса вложения из сохранённой карточки изображение не скачивается повторно; пока адрес недоступен, кнопка неактивна. Ссылка Azure требует доступа получателя к Azure.

Звёздочка раскрывает текущий чат и добавляет картинку как обычное вложение к следующему сообщению, сохраняя уже выбранные файлы. Сообщение автоматически не отправляется. Пока показывается «Загружаю изображение…», отправка недоступна; дождитесь появления вложения. Голосовой текст, полученный во время загрузки, остаётся в поле для последующей отправки. При отправке модель сразу читает вложение: дополнительно просить прочитать его не нужно. Прикрепление не создаёт новый чат и не меняет данные Azure. Пока идёт ответ или чат ещё не готов, дождитесь завершения и повторите прикрепление. Ошибка загрузки/размера показывается в попапе; прежние вложения сохраняются.

Изображения во вложениях отправленного сообщения отображаются превью с номером вложения и именем файла. Нажатие открывает общий просмотрщик с масштабированием. Превью доступно во время отправки и после повторного открытия истории чата. Текстовые файлы остаются компактными бейджами.

Для «Azure приоритета» используйте azurePriority: list_tickets и read_selected_tickets возвращают его через fields. Сортировка sortBy=azurePriority числовая, пустые значения идут последними. list_tickets и search_ticket_content поддерживают фильтр azurePriority числом или массивом чисел (ИЛИ внутри, И между фильтрами). Поле только для чтения; priority по-прежнему обозначает локальный приоритет. Инструменты экспорта поддерживают столбец azurePriority.

В согласуемом запросе внешнего Azure-поиска azurePriority также доступен массивом чисел; выбранные приоритеты показываются в вопросе подтверждения и применяются в WIQL на стороне Azure.

Поле priority — «Локальный приоритет»: положительное целое число без настроенного количества уровней, 1 — самый высокий/default. Ассистент может читать, сортировать, фильтровать и изменять его; Azure приоритет остаётся отдельным полем только для чтения.

Фильтр azurePriority в list_tickets и search_ticket_content соответствует фильтру «Azure приоритет» в списках интерфейса; применяется и к сохранённой корзине согласно lifecycle. Массив значений означает ИЛИ, другие фильтры объединяются через И.
