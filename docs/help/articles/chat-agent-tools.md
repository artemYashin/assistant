# Инструменты чата

Чат и ревью используют отдельные экземпляры одного Agent. Реализации инструментов общие, но доступные наборы различаются. Чат может отвечать во время одного выполняющегося ревью; остановка чата не останавливает ревью. Несколько ответов чата одновременно не запускаются. Лимиты провайдера могут влиять на оба запроса.

Сначала чат получает краткий каталог. `load_tools` подключает схемы только нужных инструментов; статьи справки не загружаются автоматически.

| Область | Инструменты и назначение |
| --- | --- |
| Помощь | `search_app_help`, `read_app_help`: поиск кратких выдержек и чтение статьи по явному запросу помощи с приложением. |
| Память | `list_memories`, `read_memory`: краткий каталог и детали; `save_memory`, `propose_memory`: предложения через подтверждение; `read_memory_proposal`, `edit_memory_proposal`: чтение и уточнение предложения. |
| Поиск тикетов | `list_tickets`, `get_ticket`, `get_ticket_catalog`, `search_ticket_content`: локальные сводки, типы/статусы, поиск в содержимом и заметках. |
| Содержимое | `get_cached_ticket_content`, `get_cached_ticket_content_batch`, `get_ticket_links`, `get_ticket_links_batch`, `cite_ticket_content`: кэшированные тексты, ссылки, картинки и проверенные цитаты. |
| Azure | `get_ticket_states`: допустимые статусы; `request_azure_ticket_lookup`, `lookup_azure_tickets`: план поиска и выполнение одобренного поиска; `change_ticket_status`: изменение статуса в Azure. |
| Локальные тикеты | `add_local_ticket`: импорт/восстановление; `remove_local_ticket`: локальная корзина; `get_local_ticket_metadata`, `update_local_ticket_metadata`, `list_local_tags`: заметки, теги, локальный приоритет и `localDeadline`. `batch_update_tickets`: пакетный импорт и изменения. |
| Разработчики | `list_local_developers`, `set_local_ticket_developers`: доступные локальные разработчики из общего, заказчика и проектного уровней, назначения. |
| Поиск и завершение напоминаний | `search_calendar_reminders`: все уровни и завершённые записи, буквальный поиск или RE2, фильтры, сортировка и пагинация. `prepare_calendar_status_change`: подтверждение завершения/возобновления обычной записи, сегодняшней итерации или явно указанной всей серии. Без подтверждения данные не меняются. |
| Календарь | `get_calendar_context`: текущее время, часовой пояс, уровни и локальные разработчики; `prepare_calendar_reminder`: открыть заполненную форму напоминания без даты, на время или с длительностью, в том числе ежедневно (`repeatDaily: true`). Создание подтверждает пользователь. Только чат, не ревью. |
| Контекст | `get_workspace_context`: настройки заказчика, проекта, репозитория и разработчиков. |
| PR | `list_pull_requests`, `get_pull_request`: локальный список, детали и сохранённое ревью; `request_pull_request_review`: постановка ревью в очередь. |
| Синхронизация | `sync_tickets`, `sync_pull_requests`: только по явному запросу пользователя, согласно настройкам импорта. |
| Окна и экспорт | `show_ticket_details`, `close_ticket_details`: открыть/закрыть деталку; `read_selected_tickets`: выбранные тикеты или текущий экспорт; `show_ticket_export`: открыть экспорт; `edit_ticket_export`: менять тикеты и столбцы открытого/свёрнутого экспорта, предварительно прочитав его состояние. |
| Код | `code_work_status`: очередь Git; `code_branches`: поиск веток; `code_tree`: дерево; `code_search`: поиск; `code_read_file`: чтение диапазонов; `cite_code`, `show_code_branches`: кликабельные ссылки. Доступ зависит от разрешения чтения кода в настройках ассистента. |
| Изображения | `read_image`: загрузка пикселей по ссылке только по просьбе пользователя. Явно прикреплённые изображения модель получает как вложения без дополнительной просьбы. |

Инструменты не дают произвольный shell или редактирование файлов репозитория. Ограничения согласия на чтение деталей, подтверждений памяти и доступа к выбранному контексту продолжают действовать. [Набор ревью](review-agent-tools.md) значительно уже.

Например, «Напоминай каждый день в 9:00 проверить сборку»: ассистент уточняет текущее время и часовой пояс через `get_calendar_context`, затем передаёт `repeatDaily: true` в форму. Возможность ежедневного повтора указана уже в кратком каталоге инструментов. Проверьте первую дату и время, затем подтвердите создание.

В `list_tickets` и `search_ticket_content` параметр `overdueDeadline: true` выбирает тикеты с прошедшим локальным дедлайном, без учёта статуса Azure и завершения напоминания. Без срока тикеты исключаются. Условие объединяется с другими фильтрами через И; `lifecycle` отдельно задаёт активные тикеты, корзину или оба списка. `false`/отсутствие параметра не ограничивает сроки.
