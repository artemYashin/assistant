# Инструменты чата

Чат и ревью используют отдельные экземпляры одного Agent. Реализации инструментов общие, но доступные наборы различаются. Чат может отвечать во время одного выполняющегося ревью; остановка чата не останавливает ревью. Несколько ответов чата одновременно не запускаются. Лимиты провайдера могут влиять на оба запроса.

Сначала чат получает краткий каталог. `load_tools` подключает схемы только нужных инструментов; статьи справки не загружаются автоматически.

| Область | Инструменты и назначение |
| --- | --- |
| Помощь | `search_app_help`, `read_app_help`: поиск кратких выдержек и чтение статьи по явному запросу помощи с приложением. |
| Память | `list_memories`, `read_memory`: краткий каталог и детали; `save_memory`, `propose_memory`: предложения через подтверждение; `read_memory_proposal`, `edit_memory_proposal`: чтение и уточнение предложения. |
| Поиск тикетов | `list_tickets`, `get_ticket`, `get_ticket_catalog`, `search_ticket_content`: локальные сводки, типы/статусы, поиск в содержимом и заметках. |
| Содержимое | `get_cached_ticket_content`, `get_cached_ticket_content_batch`, `get_ticket_links`, `get_ticket_links_batch`, `cite_ticket_content`: кэшированные тексты, ссылки, картинки и проверенные цитаты. |
| Azure | `get_ticket_states`: допустимые статусы; `request_azure_ticket_lookup`, `lookup_azure_tickets`: план поиска и выполнение одобренного поиска; `change_ticket_status`: изменение статуса в Azure. |
| Локальные тикеты | `add_local_ticket`: импорт/восстановление; `remove_local_ticket`: локальная корзина; `get_local_ticket_metadata`, `update_local_ticket_metadata`, `list_local_tags`: заметки, теги, локальный приоритет и `localDeadline`. `batch_update_tickets`: пакетный импорт и изменения. |
| Разработчики | `list_local_developers`, `set_local_ticket_developers`: доступные локальные разработчики из общего, заказчика и проектного уровней, назначения. |
| Поиск и завершение напоминаний | `search_calendar_reminders`: все уровни и завершённые записи, буквальный поиск или RE2, фильтры, сортировка и пагинация. `change_calendar_reminders`: прямое пакетное завершение, возобновление или удаление по явной просьбе; дедлайны тикетов вместо удаления завершаются. |
| Календарь | `get_calendar_context`: текущее время, часовой пояс, уровни и локальные разработчики; `get_calendar_reminder`: полное содержимое перед редактированием; `save_calendar_reminder`: сразу создать или изменить напоминание, в том числе ежедневное (`repeatDaily: true`); `update_calendar_warning`: сразу изменить индивидуальное предупреждение. | Контекст | `get_workspace_context`: настройки заказчика, проекта, репозитория и разработчиков. |
| PR | `list_pull_requests`, `get_pull_request`: локальный список, детали и сохранённое ревью; `request_pull_request_review`: постановка ревью в очередь. |
| Синхронизация | `sync_tickets`, `sync_pull_requests`: только по явному запросу пользователя, согласно настройкам импорта. |
| Окна и экспорт | `show_ticket_details`, `close_ticket_details`: открыть/закрыть деталку; `read_selected_tickets`: выбранные тикеты или текущий экспорт; `show_ticket_export`: открыть экспорт; `edit_ticket_export`: менять тикеты и столбцы открытого/свёрнутого экспорта, предварительно прочитав его состояние. |
| Код | `code_work_status`: очередь Git; `code_branches`: поиск веток; `code_tree`: дерево; `code_search`: поиск; `code_read_file`: чтение диапазонов; `cite_code`, `show_code_branches`: кликабельные ссылки. Доступ зависит от разрешения чтения кода в настройках ассистента. |
| Изображения | `read_image`: загрузка пикселей по ссылке только по просьбе пользователя. Явно прикреплённые изображения модель получает как вложения без дополнительной просьбы. |

Инструменты не дают произвольный shell или редактирование файлов репозитория. Ограничения согласия на чтение деталей, подтверждений памяти и доступа к выбранному контексту продолжают действовать. [Набор ревью](review-agent-tools.md) значительно уже.

Например, «Напоминай каждый день в 9:00 проверить сборку»: ассистент уточняет текущее время и часовой пояс через `get_calendar_context`, затем сохраняет через `save_calendar_reminder` с `reminder.repeatDaily: true`. Возможность ежедневного повтора указана уже в кратком каталоге инструментов. Ассистент сообщает дату и время после успешного сохранения.

В `list_tickets` и `search_ticket_content` параметр `overdueDeadline: true` выбирает тикеты с прошедшим локальным дедлайном, без учёта статуса Azure и завершения напоминания. Без срока тикеты исключаются. Условие объединяется с другими фильтрами через И; `lifecycle` отдельно задаёт активные тикеты, корзину или оба списка. `false`/отсутствие параметра не ограничивает сроки.

`change_calendar_reminders` поддерживает конкретную дату `day` для `target: occurrence`, в том числе будущую. Каждая пачка атомарна; результаты содержат количества удалённых, завершённых и возобновлённых записей. Перед массовой обработкой собираются все страницы поиска. Напоминания о дедлайнах при удалении завершаются без очистки срока тикета.

Повторы поддерживают `reminder.repeatWeekdays` (1–7, Пн–Вс) вместе с `repeatDaily: true`, по умолчанию все дни. Ассистент также создаёт постоянные напоминания «Без времени» через null в начале и окончании, без повтора. Полные сведения и поиск возвращают выбранные дни недели.

`save_calendar_reminder` возвращает также начало, индивидуальный и фактический интервал предупреждения и `warningStart`. При создании без отдельной просьбы об интервале ассистент наследует настройку (`leadMinutes: null` или поле пропущено); относительная дата «через пять минут» не означает отключение предварительного предупреждения.

В `search_calendar_reminders` статус `recurring` означает любую серию с повторением, включая завершённую сегодня или целиком; `completed: "open"` исключает завершённые целиком серии. Текущий статус в результате остаётся фактическим (`today_completed`, `completed` и т. д.).

`search_calendar_reminders` поддерживает `types: ["reminder", "ticket"]`: `reminder` — все обычные напоминания, включая повторяющиеся, с длительностью и без времени; `ticket` — дедлайны тикетов. В результате есть поле `type`. Пустой массив или отсутствие `types` не ограничивает тип. Внутри массива — ИЛИ, между типом, состояниями, заказчиками, проектами, датами и другими фильтрами — И. `statuses: ["active"]` соответствует «Все активные» (не завершённые целиком). Прежний `kinds` сохраняется для более точного выбора, например `daily`. Существующие фильтры по статусам, включая `recurring` и `today_completed`, заказчикам и проектам поддерживают массивы. Настройка фильтров интерфейса не ограничивает поиск ассистента автоматически: он передаёт нужные параметры при поиске.

Отпуска доступны через `types: ["vacation"]` и `kinds: ["vacation"]` в `search_calendar_reminders`, вместе с датами, статусами, уровнем и разработчиками. Результат содержит `vacation` (ID разработчика, даты включительно, пояс, возвращение), `warningStart` и фактический интервал предупреждения. `list_local_developers` возвращает `vacationStart`, `vacationEnd`, `vacationZone`. `get_calendar_context` возвращает общий `vacationLeadMinutes`. Завершение или удаление напоминания об отпуске выключает уведомления, но не отменяет период отсутствия; после даты возвращения уведомления прекращаются автоматически. `update_calendar_warning` поддерживает отпуск. Даты отпуска меняются в настройках разработчика или через `set_developer_vacation`; обычное сохранение календарного события их не изменяет. Подробности: [Отпуска разработчиков](developer-vacations.md).

`set_developer_vacation` задаёт или меняет один отпуск (`developerId`, `vacation: {start, end}` — даты YYYY-MM-DD включительно), либо отменяет его (`vacation: null`) вместе со связанным событием. Только по явной просьбе; сначала `list_local_developers` для точного ID, уровня, периода и пояса, при неоднозначном имени — уточнение. При изменении одной даты сохраняется вторая. Доступны разработчики текущего проекта, заказчика и общего списка. Это отмена фактического отпуска, в отличие от завершения напоминания через `change_calendar_reminders`. Результат содержит дату возвращения и обновлённого разработчика. Календарь и страница разработчиков обновляются после успеха. Инструмент есть только у чата, не у ревью.
