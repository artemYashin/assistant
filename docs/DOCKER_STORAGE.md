# Docker: данные в папках проекта

| Папка | Что внутри | Путь в контейнере |
| --- | --- | --- |
| `docker-data/orbit` | SQLite, ключ `master.key`, настройки, чаты и вложения Orbit | `/data` |
| `docker-data/repositories` | Локальные копии Git-репозиториев | `/cache` |
| `docker-data/repo-control` | Внутренний ключ Orbit ↔ code-browser | `/repo-control`, `/control` (только чтение) |
| `docker-data/whisper` | Кэш моделей Whisper/Hugging Face | `/models` |

Все пути находятся рядом с compose.yaml. Папки исключены из Git и Docker build context. BuildKit-кэш сборки остаётся под управлением Docker: это не данные приложения.

## Первый запуск

Запустите Rancher Desktop с движком dockerd (moby), затем из папки проекта выполните:

```bash
bash scripts/first-start.sh
```

Скрипт создаёт папки с правами сервисов, собирает образы и запускает приложение. Это команда только для новой установки: существующие папки не перезаписываются. Подробнее — [пошаговая установка](../GETTING_STARTED.md).

Подготовка нужна потому, что сервисы работают не от root: Orbit и code-browser — UID/GID 1000, voice — 10001. Compose намеренно не создаёт отсутствующие папки автоматически. Не меняйте владельцев всех папок на одного пользователя.

## Обновление и повторный запуск

Из той же папки проекта:

```bash
docker compose stop && git pull --ff-only && docker compose up --build -d
```

Для запуска уже собранного приложения достаточно `docker compose up -d`. Папки данных сохраняются при пересоздании контейнеров и при `docker compose down`. Не удаляйте `docker-data/` ради обновления.

Клон проекта в соседнюю папку использует своё отдельное хранилище. Данные существующей установки автоматически в него не попадут.

## Резервная копия и восстановление

1. Остановите сервисы командой `docker compose stop`.
2. Скопируйте всю папку `docker-data/` в безопасное место с сохранением прав и симлинков. Проверьте, что копия создана полностью и читается.
3. Запустите сервисы командой `docker compose up -d`.

`docker-data/orbit` сохраняйте целиком, включая базу и `master.key`: без прежнего ключа сохранённые токены не расшифровать. Не публикуйте резервные копии, базу или ключи. Не изменяйте SQLite и Git-кэш внешними программами во время работы сервисов.

Для восстановления остановите сервисы и сохраните отдельную копию текущих данных. Восстановите проверенную резервную копию `docker-data/` в папку проекта с исходными правами и симлинками, не смешивая файлы разных копий. Используйте совместимую версию приложения. После запуска проверьте проекты, тикеты, память, чаты, вложения и подключения. Восстановление возвращает состояние на момент резервной копии.

## Если запуск не удался

- Docker недоступен: запустите Rancher Desktop и проверьте `docker info`.
- Папки не найдены: для новой установки выполните `first-start.sh`; для существующей проверьте расположение данных. Не создавайте пустую установку вместо потерянной папки.
- Ошибка сборки после подготовки папок: устраните причину и повторите `docker compose up --build -d`; повторная инициализация не нужна.
- Ошибка доступа: проверьте доступ движка к папке проекта и права пользователей сервисов. Не используйте `chmod -R 777`.
- На Windows храните проект в Linux-файловой системе WSL, а не в `/mnt/c`, чтобы корректно работали права и симлинки.

Для диагностики:

```bash
docker compose ps
docker compose logs --tail=100 orbit code-browser voice
```

Перед передачей логов удаляйте секреты и приватные данные.
