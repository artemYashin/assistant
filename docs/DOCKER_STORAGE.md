# Docker: данные в папках проекта

| Папка | Что внутри | Путь в контейнере |
| --- | --- | --- |
| `docker-data/orbit` | SQLite, ключ `master.key`, настройки, чаты и вложения Orbit | `/data` |
| `docker-data/repositories` | Локальные копии Git-репозиториев | `/cache` |
| `docker-data/repo-control` | Внутренний ключ Orbit ↔ code-browser | `/repo-control`, `/control` (только чтение) |
| `docker-data/whisper` | Кэш моделей Whisper/Hugging Face | `/models` |

Все пути находятся рядом с compose.yaml. Папки исключены из Git и Docker build context. BuildKit-кэш сборки остаётся под управлением Docker: это не данные приложения.

## Перенос существующей установки

1. Обновите исходники. **До переноса не запускайте новый `docker compose up` и не удаляйте старые контейнеры/volumes.** Запустите Docker Desktop/daemon.
2. Из папки проекта выполните:

   ```sh
   bash scripts/migrate-docker-storage.sh
   ```

   Если раньше использовали `docker compose -p другое-имя`, укажите то же имя:

   ```sh
   bash scripts/migrate-docker-storage.sh --project другое-имя
   ```

   Имена установок можно посмотреть через `docker compose ls -a`. Скрипт учитывает также `COMPOSE_PROJECT_NAME` из окружения/.env. Скрипт рассчитан на стандартные четыре volumes Orbit; при нестандартных mounts или нескольких контейнерах одного сервиса он остановится для ручной проверки.

3. Скрипт сначала проверяет источники и свободные целевые пути, при необходимости скачивает вспомогательный образ `python:3.12-slim-bookworm`, затем останавливает три сервиса. Копирует данные во временную папку внутри `docker-data`, сохраняет права, UID/GID, симлинки (важно для моделей), проверяет состав, права и SHA-256 каждого обычного файла. Содержимое файлов в лог не выводится.
4. Только после успешной проверки всех четырёх копий они становятся рабочими папками. Скрипт запускает `docker compose up -d --build` с тем же именем проекта и показывает состояние сервисов.
5. Откройте http://localhost:43871. Проверьте вход со старым паролем, заказчиков/проекты, тикеты, память, историю чатов и вложения, доступ к репозиторию и голос. При необходимости:

   ```sh
   docker compose ps
   docker compose logs --tail=100 orbit code-browser voice
   ```

   Для нестандартного имени добавляйте `-p другое-имя` к этим и последующим Compose-командам.

**Исходные named volumes остаются нетронутыми.** Не удаляйте их, пока не убедитесь, что перенос успешен. Они являются снимком на момент остановки; дальнейшие изменения в папках в них не копируются. Понадобится дополнительное место для полной копии всех данных, включая Git и модели. Проверка больших кэшей может занять время.

## Ошибка или повторный запуск

- Docker недоступен: запустите Docker Desktop/daemon и повторите команду. Ничего ещё не переносилось.
- Volume не найден: проверьте имя проекта. Не используйте `--init` для обхода этой ошибки, если ожидаете старые данные.
- Целевая папка уже существует: скрипт не объединяет и не перезаписывает данные. Если миграция уже завершилась, запускайте обычный `docker compose up -d --build`.
- Ошибка копирования/проверки: исходные volumes сохранены, сервисы остаются остановленными. Частичная копия остаётся в `docker-data/.migration-*`; не используйте её как рабочие данные. Устраните причину (место, права, файловая система). Перед повтором можно удалить только эту неудачную временную копию, убедившись, что другой перенос не выполняется.
- После аварийного прерывания может остаться пустая папка `.migration-lock`. Удаляйте её только когда скрипт действительно больше не работает.
- Ошибка сборки/запуска после переноса: готовые папки сохранены. Исправьте ошибку и повторите `docker compose up -d --build`; перенос повторять не нужно.
- На Windows храните проект в Linux-файловой системе WSL, а не на диске `/mnt/c`: Git-кэш, симлинки и Linux-права должны поддерживаться. На Docker Desktop Mac используйте папку, доступную Docker для file sharing.

## Откат на старые volumes

Сохранён `compose.named-volumes.yaml` с прежними mounts. Если новые контейнеры уже запущены, сначала остановите их. Затем запустите старую конфигурацию **с тем же именем проекта**:

```sh
docker compose stop
docker compose -f compose.named-volumes.yaml up -d
```

Для нестандартного имени:

```sh
docker compose -p другое-имя stop
docker compose -p другое-имя -f compose.named-volumes.yaml up -d
```

Откат вернёт состояние данных на момент миграции. Изменения, сделанные после миграции, останутся в `docker-data`, но не появятся в старых volumes. Не запускайте обе конфигурации одновременно. Ни при миграции, ни при откате не нужен `down -v`.

## Новая установка и обычное обновление

Только для новой установки без старых volumes:

```sh
bash scripts/migrate-docker-storage.sh --init
```

Подготовка нужна потому, что сервисы работают не от root: Orbit и code-browser — UID/GID 1000, voice — 10001. Compose намеренно не создаёт отсутствующие папки автоматически, чтобы не открыть пустую базу вместо существующих данных.

Дальнейшее обновление:

```sh
git pull
docker compose up -d --build
```

Для резервной копии останавливайте сервисы и сохраняйте папки вместе с правами. `docker-data/orbit` копируйте целиком, включая базу и `master.key`. Не открывайте и не изменяйте SQLite/файлы Git-кэша внешними программами во время работы сервисов.
