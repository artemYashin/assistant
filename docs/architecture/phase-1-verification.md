# Проверка первого этапа FSD — 27 октября 2026

Исходная версия: коммит `097422c`, приложение `0.32.1`.
Этап не меняет пользовательское поведение и не повышает версию приложения.

## Проверено

- `npm run architecture:check`: семь тестов правил зависимостей и проверка
  настоящего дерева исходников.
- `npm run check`: архитектура, версии, свежесть индексов справки и TypeScript.
- `npm run build`: production Vite bundle и серверная компиляция. Предупреждение
  о крупных chunks остаётся; оптимизация размеров не входит в этот этап.
- Сравнение AST 63 изменённых существующих TS/TSX/CSS-файлов с исходным коммитом:
  исполняемые инструкции совпадают после исключения import/re-export,
  добавленного `export` у App и перенесённого запуска React. CSS перенесён без
  изменений. Новые index-файлы только экспортируют прежние реализации.
- Серверные исходники, SQL, Docker, package-lock и src/releases.json не изменены.
- ID и имена файлов автоматических статей справки сохранены; ссылки на исходники
  и coverage обновлены.
- В production preview с вымышленными API-ответами проверены страницы «Что нового»,
  «Разработчики», «Календарь», «Тикеты», «Настройки», «Подтверждения».
- В браузере проверены прежняя ширина чата, сохранённый вид/поиск календаря,
  ключ просмотренной версии и открытие/отмена подтверждения памяти.
- Три полные перезагрузки страницы разработчиков с искусственно медленными
  настройками: нет прежнего падения на null calendarNotifications.

Браузерные проверки не отправляют запросы в Azure/Copilot и не читают живые
пользовательские данные. Они проверяют UI и интеграцию модулей, а не внешние сервисы.

## Полный набор тестов: исходные проблемы

До изменения: 625 тестов, 620 проходят, 5 падают.
После изменения: те же 625 тестов, те же 620 проходят, те же 5 падают.
Новых падений не обнаружено. Полный набор нельзя считать зелёным.

1. `tests/chat-files.test.ts`: upload API validates files and binds downloads and
   conversation requests to the chat — ожидается 200, получается 409.
2. `tests/chat-management.test.ts`: chat receives selected ticket IDs and rejects
   stale Azure selection — ожидается 200, получается 409.
3. `tests/ticket-metadata.test.ts`: chat metadata tool reports actionable validation
   errors instead of generic SDK failure — исключение в обработчике проверки схемы.
4. `tests/usage.test.ts`: review feedback tools are limited to memory reads,
   questions and proposals — ожидается одно предложение памяти, получается ноль.
5. `tests/usage.test.ts`: 23 confirmed local tag edits use two model calls and trace
   child operations separately — ожидается 23 дочерних вызова, получается ноль.

Эти ошибки зафиксированы отдельным прогоном до переносов. Проверки и серверная
логика этих пяти сценариев не изменялись ради получения зелёного результата.
Разбор и исправление требуют отдельной задачи.

## Данные и миграции

Миграция данных не требуется: меняются пути исходных модулей, а не форматы
пользовательского хранения. Существующие тесты обновления заполненных БД,
повторного открытия, сохранения разработчиков/поручений/отпусков и истории
продолжают проходить в полном наборе.

Это не гарантия отсутствия любых ошибок. Реальные внешние интеграции и все
возможные пользовательские наборы данных не проверялись. Живые БД и файлы
пользователей не открывались, не переносились и не удалялись.
